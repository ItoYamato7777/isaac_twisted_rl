# 実験記録

`logs/`・`outputs/` は git の管理外で、消えると戻らない。結果を再現するための情報は、ここで書く記録にしか残らない。

## 1. メタデータを集める

| 項目 | 取り方 |
|---|---|
| commit | 学習を始めた時点の `git rev-parse --short HEAD` (STATUS の「走っているジョブ」に書いたもの) |
| 未コミットの差分 | run の `git/*.diff` が空か。空でなければ「あり」と書き、パスを書く。未追跡のファイルは diff に入らない |
| シード・iteration・run 名 | run の `params/agent.yaml` (`seed`・`max_iterations`・`run_name`) と、最後の `model_<it>.pt` |
| num_envs・プリセット・物理の上書き | run の `params/env.yaml` |
| コマンド | 学習と評価のコマンドを、Hydra の上書きを含めてそのまま |
| 評価 JSON | `eval_chain_it<it>.json` などのパス |

分からない項目は空欄にせず「記録なし」と書く。

## 2. 書く: `docs/experiments/YYYY-MM-DD_<英小文字とハイフンの題>.md`

日付は学習 (計測) を始めた日。テンプレート:

```markdown
# <題> (YYYY-MM-DD)

- 状態: 凍結
- 読むべき状況: <一文>

## 要約

- 結論: <2〜3 文。「結論」の「分かった」の要点>
- 有効か: <シード数・比べる相手の欠け・後で否定された推測など、使うときの限定>

## 目的と仮説
## 条件
| 項目 | 値 |
|---|---|
| commit | <hash> (未コミットの差分: なし / あり → パス) |
| タスク ID とプリセット | |
| 変えた変数 | |
| シード | |
| iteration (最後のチェックポイント) | |
| num_envs | |
| 学習のコマンド | |
| 評価のコマンド | |
| run のフォルダ | logs/rsl_rl/<ログ名>/<日時>_<run 名> (シードごと) |
| 評価 JSON | |
| 無効にした run | (あれば。退避先と理由) |
## ゲート (学習の前の確認)
## 結果
(表。指標・シードごとの値・標準誤差)
## 結論
- 分かった:
- 推測:
- 未確認:
## 次の作業
```

- 否定的な結果も書く。
- 「要約」は読む側が最初に読む所。後の記録で結論の扱いが変わったら (推測が否定された・原因が別に見つかった)、要約の「有効か」を書き換えてよい。
- 書いた後は本文を書き換えない (凍結)。後で分かったことは、新しい記録を作るか、冒頭に引用ブロックで注記を足す。
- 本文が 20 KB を超えたら、要約のファイル (`<名前>.md`: 要約と全文の目次) と全文 (`<名前>_detail.md`) に分ける。節番号・行番号の参照は全文を指す。
- `docs/experiments/README.md` の一覧に 1 行足す (数値は書かない)。
- 次の作業は `docs/STATUS.md` に写す (skill `handoff`)。設計の判断を変えたなら `docs/decisions/` に書く。

## 3. 結果を無効にするとき

1. 無効の理由と、どの run・どの出力が対象かを決める。ユーザーに確かめてから動かす (管理外のデータ)。
2. 対象を消さずに、同じ階層の `_invalid/` に `mv` する。道具の多くは「出力があれば飛ばす」ので、退避しないと古い結果が使われる。
3. 実験記録に、元のパス・退避先・理由を書く。`logs/` の中に README を手で書かない (記録は追跡する文書に置く)。
