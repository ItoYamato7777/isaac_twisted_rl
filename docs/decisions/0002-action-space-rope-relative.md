# 0002 行動空間: ロープ相対 + `Δlink`

- 状態: 有効 (v0〜v7 のすべてに適用。範囲の値だけ版で変わる)
- 読むべき状況: 行動のチャネル・範囲・座標系を変えたくなったとき。置き先を絶対座標にしたくなったとき
- 最終更新: 2026-10-04

## 決定

1 手 ([0001](0001-kinematic-hand-and-one-move.md)) の指示は次の 6 次元 (離散 2 + 連続 4)。

```
grasp_link_id  離散 {2, ..., N-3}     掴むリンク
delta_link     離散 {-8, ..., +8}     → target_link_id = clip(grasp_link_id + delta_link, 0, N-1)
drop_x_rel     連続 ±0.15 L           target_link の現在位置からの xy 変位 (L = ロープ全長)
drop_y_rel     連続 ±0.15 L
drop_z_rel     連続 0 〜 3 ロープ直径  置くときの高さ (把持高さからの上乗せ)
end_yaw        連続 ±π                置き終わりの手首 yaw
```

- `via_*` (中間経由点) は入れない。
- RSL-RL の PPO には離散ヘッドが無いので、6 チャネルすべてを連続 `[-1,1]` で受け取り、`grasp_link` / `delta_link` は `PickPlaceAction` の側で丸める。方策から見れば連続、環境に入る値は離散なので、設計意図は保たれる。
- v3 以降は `drop_xy` を ±0.30 L に広げる ([0014](0014-gate1-wiring-for-knot.md))。v5 は `drop_z` を離すときの指先の高さ 50〜100 mm (`GraspLimits.release_tip_z`) に写す (`kt/common/README.md` §3)。

## 理由

### 置き先を絶対座標にせず、リンク相対にする

旧 §4.1 は「Step 6 の設計で最も重要な判断」として根拠を 4 つ挙げる。

1. **人間が設計した最良の手順ですら、リンク相対でしか書けなかった。** Step 5 の台本の 2 手目は、渡し先をリンク K の現在位置から実行時に決めている (`GraspMove.over_link_frac`)。1 手目の結果が物理次第で毎回違うので、絶対座標の決め打ちでは本体を越えられなかった。これが一番強い経験的根拠。
2. **pick&place の粒度では、離した瞬間にロープが物理で動く。** 次のアクションを決める時点で、リンク位置は前回と違う。置き場所を絶対座標で持つ意味がほぼ無い。
3. **絶対座標にすると「微小操作」の学習が逆に難しくなる。** 「リンク i を 2 cm 右へ動かす」という同じ意図が、リンク i の現在位置によって毎回違う出力値になる。リンク相対なら、この引き算が座標系のレベルで埋め込まれる (object-centric action space)。
4. **キネマティックハンドなので、絶対座標を使う利点が無い。** 可達領域の制約が無い。

### 交差を作るには「たるみ」が要る (旧 §3(b))

真っ直ぐなロープでは、掴んだ点 G からロープ上の点 K までの弧長は直線距離に等しい。一方、ハンドが G から K の向こうへ回り込む経路は必ずそれより長い。そのため、経路長が弧長を超えた瞬間にロープが張り切り、**端だけが本体を渡るのではなく、ロープ全体が平行移動する**。台本は 2 段構え (1 手目でロープを大きく曲げてたるみを稼ぎ、2 手目でそのたるみの範囲内で端を本体の上に渡す) にし、渡し先をリンク K の現在位置から実行時に決めた。床の摩擦 (`GROUND_FRICTION`) も同じ理由で効く: ロープが床の上で滑りすぎると、掴んで運ぶ操作がロープ全体の平行移動になって交差が作れない (`kt/common/env_cfg_base.py:64-65`)。

### `target_link_id` そのものではなく `Δlink` にする

- `grasp_link_id` と `target_link_id` を独立に選ばせると、N×N (20 リンクなら 400 通り) の離散ペアになる。`Δlink` なら 20×17 で済む。
- `Δlink` は「隣を掴む」「8 個先を狙う」という**状況によらない意味**を持つので、方策が汎化しやすい。

### 「1 アクションで必ず位相が変わってしまうのでは」への回答

変わるかどうかは、`drop_*_rel` の範囲と `Δlink = 0` を許すかで決まる。

- `delta_link = 0` → 掴んだリンクのすぐ近くに置き直す = **微調整モード**
- `delta_link = ±8` → 本体の向こう側へ渡す = **位相を変えるモード**

「少しずつ操作する」は、アクション内の微小変位ではなく、**複数回の pick&place** として表現される。Step 5 の台本 (1 手目: たるみ作り / 2 手目: 渡す) がまさにこれ。

### 端リンクを除外する

端ちょうどを掴むと、接触面積が足りずに滑る。そのため `grasp_link_id` は `{2, ..., N-3}` に制限する。`target_link_id` の側は範囲を絞る必要が無いので、`{0, ..., N-1}` に clip する。
