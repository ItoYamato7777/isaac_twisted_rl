- 読むべき状況: v10 を実装するとき。段 (`BfsPotential.stage`) の定義を変えたくなったとき。段のアーカイブに入る形を絞りたくなったとき
- 最終更新: 2026-10-07

## 決定

v10 = v7 + **段の定義の差し替え** (1 版 1 変数。`stage_weights` は v7 の 1:1:1。v8・v9 の変更は入れない)。

段 0〜2 に入るのは、下の表の p-data (R2 除去の **前** の生の p-data) だけ。段 3 (固結び) は **v7 と同じ判定** (`BfsPotential.stage` >= 3)。
段 0〜2 の表に無く、段 3 でもない形は **道から外れた形** (段 −1) とする。

| 段 | 意味 | p-data | 数 |
|---|---|---|---|
| 0 | 結び目なし | `` (交差なし) | 1 |
| 1 | 輪が 1 つ | `1O2-_2U1-`、`1U2+_2O1+` | 2 |
| 2 | 輪に端を通した | `1O3-_2U4-_3U1-_4O2-`、`1O3+_2U4+_3U1+_4O2+` (Fig.1)、`1U3-_2O4-_3O1-_4U2-`、`1U3+_2O4+_3O1+_4U2+` (台本) | 4 |

正規の手 (論文の引数の順。R1 は (index, left, sign)、C は (over, under, sign)):

| 経路 | 段 0 -> 1 | 段 1 -> 2 | 段 2 -> 3 |
|---|---|---|---|
| A (Fig.1 上) | R1(0,1,−1) | C(2,1,−1) -> `1O3-…` | C(2,4,−1) |
| A' (台本の鏡像) | R1(0,1,−1) | C(1,0,−1) -> `1U3-…` | C(0,2,−1) |
| B (Fig.1 下) | R1(0,1,1) | C(0,1,1) -> `1O3+…` | C(2,0,1) |
| B' (台本) | R1(0,1,1) | C(1,2,1) -> `1U3+…` | C(4,2,1) |

- **リポジトリの `AbstractState.Reide1` の引数は (idx, sign, left) の順で、論文と違う。** R1(0,1,−1) は `Reide1(0, sign=-1, left=1)`。
  C は `cross(over_idx, under_idx, sign)` で論文と同じ順。上の表の p-data はすべて、この関数で自明な状態から
  たどって確かめた (2026-10-06)。段 2 の 4 個のどれからも、1 手の出口 28 個のうち、厳密な段 3 の 2 個のちょうど 1 個へ 1 手、それ以外の固結び (`1O4+_2U5+_3O6+_4U1+_5O2+_6U3+`、`1U4-_2O5-_3U6-_4O1-_5U2-_6O3-` のどちらか 1 個) へ 1 手 (どちらも C で、運ぶ区間が同じで下の区間だけ違う)、残り 26 個は v7 の段 0〜2 (2026-10-06、`_enumerate_moves`)。
- 学習 (1 遷移 = 1 エピソード): 手の後に段が上がれば +1 (段 2 から厳密でない固結びに着いても段 3 なので +1)、段が下がるか **道から外れれば −1 で終了** (今の「段が下がった」と同じ扱い)、発散 −1、時間切れ 0。
- 段のアーカイブには段 0〜2 の形だけを入れる (道から外れた形は入れない)。
- 観測の段の one-hot と「次にたどる辺」(`next_edge`) は v7 と同じ形 (次元) のまま。たどる辺の中身は「正規の経路の次の手」に絞る。道から外れた形では辺なし。
- chain 評価: 固結びの判定は **v7 と同じ** (`BfsPotential.stage` >= 3。v7 と比べるため)、道から外れても 18 手まで続け、
  外れている間は段 0 の方策に打たせる。厳密な段 3 (上の 2 個) に入った割合を別の列に出す。

## 理由

- **v7 の段のアーカイブは方策の失敗で汚れていく。** v7 の段は Φ を丸めたもので、Φ の表 321 個の p-data が段 0〜3 に 1 / 40 / 108 / 172 個入る。
  表に無い形は段 0 になる。v7 seed 43 を iteration 330 まで延ばすと、段 0 のアーカイブの形の曲がり (関節角 |q| の合計) が 16.4 -> 20.8 に増えた。
  段 1・2 は変わらなかった。そこから 8 形を取り出すと、6 形が「交差 4 個・表に無い・たどる辺なし」だった (`view_archive.py --headless`)。
  学習ログでは、段 0 の時間切れが 0.7% -> 19.8%、たどる辺が無い手が 8% -> 44% に増えた。chain 評価は it100 53.7% -> it300 39.3% (1 シード)。
  段の形を正規の経路の上に限れば、アーカイブに入る形も限られる (このループの説明は推測。1 シード)。
- **経路は論文の Fig.1 に従う** (`paper/Learning_Topological_Motion_Primitives_for_Knot-Plannning.pdf`)。固結びは R1 -> C -> C の 3 手で、
  オレンジの 2 本 (A・B) は左右の鏡像。
- **段 2 に台本の C2 も入れる** (ユーザーの判断、2026-10-06)。Fig.1 の段 2 (`1O3±…`) は、ゲート 1 の台本では 1 度も通っていない
  (初期アーカイブ `outputs/archive_seed/overhand_28links.pt` の段 2 の 130 形のうち 0 形)。台本は同じ段 1・同じ固結び (経路 B と同じ p-data) を
  別の C2 (`1U3+_2O4+_3O1+_4U2+`、130 形のうち 18 形) 経由で結んでいる。pick&place では運んだ側が必ず上に置かれるので、
  どちらの経路も 1 手は「輪の側を端に被せる」手が要る。台本はそれを 2 手目にし (経路 B')、Fig.1 は最後の手にしている (経路 B)。
  Fig.1 の順が物理で通るかは確かめていない。両方を入れれば、通りやすい方を方策が選べる。
- **生の p-data で判定する** (R2 除去の前)。段ごとの p-data の数を表のとおりにするため。紐が重なっただけの偽の交差 (R2 で消える組) も道から外れる。
  台本の段 2 の残り 112 形 (3 交差の `1U4+_2O5+_3O6-_4O1+_5U2+_6U3-`、R2 除去すると段 1 と同じに見える) も外れる。
- **chain 評価の固結びを v7 と同じにする**のは、v7 と同じ物差しで比べるため。
- **段 3 は v7 と同じ判定にし、厳密な 2 個に絞らない** (ユーザーの判断、2026-10-06)。厳密な 2 個に絞ると、段 2 から 1 手で行ける
  もう 1 つの固結び (R2 除去後も固結び) が学習では −1、chain 評価では成功になり、学習と評価で食い違う。0023 の理由 (アーカイブの汚れ) は
  段 0〜2 の話で、段 3 は終了の段なのでアーカイブに入らない。段 2 の `next_edge` は正規の経路の手 (厳密な段 3 へ) だけを指す。

## 実装の見通し (実装の前に書いた推奨。実装は `versions/v10/README.md` の表が正本)

- **段の関数 (Isaac Sim なし)**: `common/topology/` に、`BfsPotential.stage(raw_batch, reduced_batch)` と同じ引数で段 (0〜3、外れたら −1) を返すクラスを足す。
  `tp.batch_keys(raw_batch)` を上の p-data のキー (`tp.p_data_key`) と引き合わせる。上の表と経路は単体テストにする。
- **差し替えの口**: 今は `tp.get_bfs_potential(env.device).stage(...)` を直接呼ぶ箇所が `common/mdp/` に 6 つある
  (`stages.py` の `current_stage`・`stage_transition`、`observations.py:294` (`NextEdgeGoal`)、`archive.py:363` (復元の検査)・`:379` (記録)、`topology_log.py:262`)。
  推奨は、env の設定の 1 つの属性 (既定は今の BFS) で段の関数を選ぶ補助関数を 1 つ足し、6 か所をそれ経由にすること。
  既定のままなら v4〜v9 の挙動は変わらない (それを確かめるテストを付ける)。項の名前は変えない (`.claude/rules/mdp.md`)。
- **道から外れた手**: `stages._outcome` で `after == -1` を `down` に含める (報酬 −1・`stage_down` で終了)。
- **観測**: 段の one-hot は −1 を段 0 に寄せる (学習では外れたら終わるので、効くのは chain 評価だけ)。
  `next_edge` は今の表 (`next_edge.py` の `NextEdgeTable`) の候補を、子が正規の経路の上にあるものに絞る。
- **Play (chain)**: 終了項 `stage_up` (chain) の固結びの判定は BFS の段のまま (`after >= STAGE_GOAL`)。厳密な段 3 の列は `eval_chain.py` に足す。
- **初期アーカイブ**: ファイルには段のラベルと関節角しか無く、p-data は物理で形を置き直さないと分からない。今の初期アーカイブは
  段 0 の 128 形・段 1 の 264 形 (すべて `1U2+_2O1+`)・段 2 の 18 形 (`1U3+_2O4+_3O1+_4U2+`) が新しい定義に入り、段 2 の 112 形は外れる。
  `outputs/archive_seed/` は上書きしない。外れた形を除いた新しいファイルを作るか、復元のときに外れた形を捨てる (今の `restore_mismatch` の検査を使う)。
  経路 A・A' (負の符号) の形は初期アーカイブに無い。
