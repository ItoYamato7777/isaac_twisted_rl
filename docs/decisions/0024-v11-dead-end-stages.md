# 0024 v11 は v7 の段のまま、表に無い「行き止まりの形」だけを −1 にする

- 状態: 有効 (v11 以降。実装は `common/topology/dead_end_stages.py` と `versions/v11/`)
- 読むべき状況: v11 を実装するとき。段の定義 (`stage_definition`) を変えたくなったとき。段 0 のアーカイブに溜まる形を減らしたくなったとき
- 最終更新: 2026-10-08
- 結果: [v11 の記録](../experiments/2026-10-07_v11_dead-end-stages.md) (iteration 300 で v7 を上回らなかった。続けるかは未定)

## 決定

v11 = v7 + **表に無い形の段の付け方の差し替え** (1 版 1 変数。v8・v9・v10 の変更は入れない。`stage_weights` 1:1:1、`next_edge` は v7 と同じ絞らない表、初期アーカイブは v7 と同じ `overhand_{num_links}links.pt`)。

段は次の順に決める (「表」は BFS の表 `knot_graph.potential_table()` の 321 個の p-data。生 = R2 除去の前):

| 順 | 条件 | 段 |
|---|---|---|
| 1 | 生の p-data が表にある | v7 と同じ (`BfsPotential.stage(raw, reduced)`) |
| 2 | 生は無いが、R2 除去後の p-data が表にある | R2 除去後の形の段 (`BfsPotential.stage(reduced, reduced)`。偽の交差を許す) |
| 3 | どちらも無く、R2 除去後のラダーの段 (`topology_class`) が 2 以上 | ラダーの段 (v7 と同じ) |
| 4 | どちらも無く、ラダーの段が 0 | **−1 (行き止まり)** |

- **R2 除去は 1 が外れたときだけ使う** (先に使わない)。表の段 2 のうち 16 個 (台本が通る cover 後 `1U4+_2O5+_3O6-_4O1+_5U2+_6U3-` を含む) と段 1 のうち 12 個は、R2 除去すると 1 つ下の段の形になる。R2 除去を先にすると、これらが落ちる。
- 学習: −1 の形は、v10 の「道から外れた」と同じく、手の前の段 (0〜2) より下なので −1 で終了 (`stage_down`)。v7 と挙動が変わるのは、段 0 から 4 の形を作った手 (v7 は「段が同じ」で続けた) と、2 で段 1 に上がる形 (v7 は段 0) だけ。段 1・2 から 4 の形へ行く手は v7 でも「段が下がった」。
- アーカイブ: −1 の形は保存されない (`StateArchive.add` が捨てる)。2 の形は R2 除去後の段で保存される。
- 観測の段の one-hot は −1 を段 0 にする (v10 で入れた `knot_stage_one_hot` の `clamp_min(0)`。v7 でも 4 の形は段 0 だったので、chain 評価の観測は v7 と同じ)。
- chain 評価: 固結びの判定は v7 と同じ (段 >= 3)。
- 学習の長さ: **seed 43 / 44 を iteration 300 まで** (ユーザーの判断、2026-10-07)。比べる相手の v7 も **seed 44 を iteration 300 まで延ばす** (延長した v7 は seed 43 の 1 本だけのため)。chain 評価は iteration 100 / 200 / 300 (できれば間の 70・90 なども) で並べて読む。

## 理由

- **v7 の段 0 の汚れは、ほぼ「表に無く、ラダーでも 0」の形だった。** v7 の段は「表に無い形はラダーの段」で、ラダーが 0 の形は段 0 になる。v7 のアーカイブの形を書き出して数えると (下の「データ」)、段 0 のうち「生も R2 除去後も表に無い」形は it100 で 9〜10%、it330 (s43 の延長) で 70%。it330 の段 0 の 1024 形のうち 613 形は `1O6+_2U5+_3O8-_4U7-_5O2+_6U1+_7O4-_8U3-` とその鏡像 `1U6+_2O5+_3U8-_4O7-_5U2+_6O1+_7U4-_8O3-` の 2 つ (交差 4 個・R2 で消えない・ラダー 0・交差 4 個以内の範囲では固結びへの道が無い)。v7 s43 の chain 評価は it100 53.7% -> it300 39.3% (1 シード。[0023](0023-v10-path-stages.md) の「理由」)。
- **v10 の詰まりは定義に由来する** ([v10 の記録](../experiments/2026-10-06_v10_path-stages.md)、chain 評価 0〜1.8%)。v7 の表の段 2 の 108 個のうち 104 個は交差 3 個で、v10 はそれを全部外した。段 1 の成功は v10 で 0.01〜0.02、v7 で 0.57〜0.58。v11 は段 1 -> 段 2 の判定を v7 のままにする。
- **偽の交差は 2 で救う。** v7 のアーカイブの段 0 の 31〜36%、段 1 の 9% が「生は表に無いが R2 除去後は表にある」形。v10 は生の完全一致なので、段 1 のアーカイブの形の 67〜69% を道から外れた扱いにしていた。
- **段 2 の表に無い形 (ラダー 2) は外さない。** v7 の段 2 のアーカイブの 28% (s43) / 48% (s44) は、交差 4 個でラダーが 2 (絡み 2 交差) の表に無い形。v7 の段 2 の形ごとの評価 (`eval_search_shapes_it100_run_det.json`、6 手・64 回) では、6 手以内の成功率が表にある形 0.30 / 0.32 (87 / 63 形)、表に無い形 0.25 / 0.21 (41 / 65 形)。低いが行き止まりではない。外すと段 1 から上がった手の 3〜5 割が −1 になり、v10 の詰まりを小さく繰り返すおそれがある (推測)。
- **効果は長い学習で出ると見込む** (推測)。it100 では v7 の段 0 の汚れは 9〜10% だけなので、it100 の比較では差が出にくい。v7 の延長で汚れが増えて chain 評価が下がった区間 (it100 -> it300) で比べる。

## 実装の見通し (推奨)

- **段の関数** (`common/topology/`、Isaac Sim なし): 上の 1〜4 を返すクラスを足し、`path_stages.get_stage_function` と `STAGE_DEFINITIONS` に新しい名前 (例 `bfs_dead_end`) を加える。v10 の `PathStage` と同じく `stage(raw_batch, reduced_batch)` で呼べる形にする。2 は `batch_keys(reduced_batch)` で表を引き、見つかった env だけ `BfsPotential.stage(reduced, reduced)` の値にする。
- **差し替えの口**は v10 で作った `common/mdp/observations.py` の `stage_function` (env の設定の `stage_definition`) をそのまま使う。`next_edge` は `get_next_edge_table(device, 定義)` が新しい名前で絞らない表を返すようにする (今は `bfs` 以外を ValueError にする)。
- **版**: `versions/v11/` は v7 を継承し、`stage_definition` だけを足す (`load_paths` は変えない)。`tests/test_v11_cfg.py` で v7 との差がそれだけであることを静的に検査する (`tests/test_v10_cfg.py` が手本)。
- **テスト**: 1〜4 の各場合、上の「データ」の代表の p-data (`1O6+_2U5+_3O8-_4U7-_5O2+_6U1+_7O4-_8U3-` が −1、`1U6-_2U5+_3O8-_4O7+_5O2+_6O1-_7U4+_8U3-` (R2 除去で交差なし) が 0、`1O4-_2O5+_3O6-_4U1-_5U2+_6U3-` (R2 除去で `1O2-_2U1-`) が 1、cover 後 `1U4+_2O5+_3O6-_4O1+_5U2+_6U3-` が 2 (R2 除去を先にしない)、`1U6-_2O5-_3O8-_4U7-_5U2-_6O1-_7O4-_8U3-` (表に無い・ラダー 2) が 2)、表の全 p-data で v7 と同じ値。
- **v11 に入れないもの** (後の版の候補): R2 除去後の形で `next_edge` を引くこと (今は偽の交差がある形は「たどる辺なし」)、段 2 の表に無い形を外すこと。
