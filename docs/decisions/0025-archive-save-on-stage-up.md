# 0025 v12 は到達状態アーカイブに「段が上がった手の後の形」だけを保存する

- 状態: 有効 (v12 以降。v12 は学習・chain 評価済み: [記録](../experiments/2026-10-13_v12_archive-stage-up.md))
- 読むべき状況: v12 を実装するとき。到達状態アーカイブの保存の規則・引き方を変えたくなったとき。学習ログの段の成功が途中で落ちたとき
- 最終更新: 2026-10-10

## 決定

v12 = v7 + **到達状態アーカイブの保存の規則の差し替え** (1 版 1 変数。v8〜v11 の変更は入れない。段の定義は `bfs`、`stage_weights` 1:1:1、初期アーカイブは v7 と同じ `overhand_{num_links}links.pt`)。

| | v4〜v11 (今) | v12 |
|---|---|---|
| 保存する手 | 毎手 (床に落ちていて発散していない手の後の形を、その形の段に) | **段が上がった手** (手の前の段 < 手の後の段、手の後の段が 1 か 2) の後の形だけ。床に落ちていて発散していない条件は今と同じ |
| 段 0 のアーカイブ | 段 0 のまま・段が下がって 0 になった手の後の形が入る | 学習中は何も入らない (台本の初期アーカイブの 128 形のまま) |
| 段 1 のアーカイブ | 段 1 の手の後の形すべて | 段 0 から上がった手の後の形だけ |
| 段 2 のアーカイブ | 段 2 の手の後の形すべて | 段 0・1 から上がった手の後の形だけ |

- 段 3 (固結び) は今と同じく保存しない。段が上がった手でも、手の後の段が 3 なら保存しない。
- 引き方 (段を 1:1:1 で選び、その段の中で一様。段 0 は確率 0.5 でまっすぐなロープ)・容量 16384・古い順に捨てる、は今のまま。
- **記録のために** アーカイブの写しを一定の間隔で別のファイルに残す (今は `archive.pt` 1 つを上書きするので、中身の推移を後から追えない)。学習の挙動は変えない。
- 学習: seed 43 / 44 を 0 から iteration 300 まで (v7・v11 と同じ長さ)。比べる相手は v7 (s43 の延長と、これから延ばす s44) と v11。

## 理由

- **今の規則は、段 k の方策の出力を段 k の訓練の分布に戻すループを作る** ([切り分けの記録](../experiments/2026-10-09_v11_stage2-archive-loop.md))。段 k の方策が抜け出せない形は、時間切れのエピソードの毎手 (最大 6 回) 書き足され、解ける形はほとんど書き足されない。古い順に捨てるので、アーカイブは方策の一番苦手な形を選び出す。v11 s43 の段 2 のアーカイブは it300 で形 A に 37%、it650 で形 B に 41% 占められ、形 B は it650 の方策でも 6 手以内の成功が 4.7% だった。段 2 のアーカイブに入る形の 7 割以上 (it600) は段 2 の方策の出力だった。
- **方策ではなく、始まりの分布が崩れていた。** it650 の方策は it300 のアーカイブの形に対して it300 の方策と同じかやや上 (6 手以内の成功 0.453 と 0.441) で、it650 のアーカイブから始めると 0.145 になった。直すべきは方策の学習ではなく、どの形から練習させるか。
- **段が上がった手だけにすると、ループの道が無くなる。** 段 k のアーカイブに入るのは段 k より下の方策が作った形だけになり、どの段でも自分の出力が自分の訓練に戻らない。
- **段 k の訓練の始まりの分布が、chain 評価で段 k に着く形の分布と同じになる。** chain 評価で段 2 の方策が最初に出会うのは、段 1 の方策が段を上げて作った形。今の規則では段 2 の訓練の 4 割が形 B から始まったが、chain 評価では段 1 の手の後に形 B は出ていない (it650 の手ごとの診断、上位 40 形に無い)。
- **論文と、0009 に書いた元の意図に戻る。** TWISTED-RL §IV-D は、交差数 k の方策の初期状態を「それより前の段の学習中に l→k (k>l) の遷移で到達した形」とする。[0009](0009-reached-state-archive.md) も v4 の意図を「段を上がった直後の形状は次の段の初期状態になる」と書いたが、実装は毎手を保存していた。
- **v7 の段 0 の汚れも同じ仕組みで、同時に止まる見込み** (推測)。v7 の延長で段 0 に溜まった行き止まりの形は、段 0 の手 (0 -> 0) と下がった手 (1 -> 0) の後に保存されていた。v12 は段 0 に何も足さない。v11 の「行き止まりを −1」は報酬も変える別の変数なので、v12 には入れず、v7 を継承して保存の規則だけを比べる。
- **新しい調整の値を持ち込まない。** 上限や優先度の式が無いので、効いたか効かなかったかがそのまま読める。

### 見込みの弱点

- **段 k の方策が、段 k のまま形を整えた後の形を練習しなくなる。** chain 評価では段 2 のまま 2 手目・3 手目を打つことがある。ただしそれらの形も、段 1 の出力の形から始めた段 2 のエピソードの中で打つので、エピソードの中では出会う。
- **難しい形への集中が無くなる。** v11 s43 では形 A に集中した後に方策が A を解けるようになった (A の割合が 37% -> 3%)。v12 で段 2 の成功が伸び悩んだら、v12 の分布を土台に、形ごとの成功率で優先度を付けて引く割合を上限つきで混ぜる (Prioritized Level Replay 型) のを次の版の候補にする。
- **段 1 の方策のずるは残る。** 段 1 の方策が、段 2 で解きにくい形に上がることで +1 を取るなら、その形は段 2 のアーカイブにその割合で入る。ただしその形は chain 評価でも同じ割合で出会うので、訓練で同じ割合で練習するのは正しい扱い。
- **アーカイブに入る量が減る。** 段 2 に入る形は 1 iteration あたり約 1750 (段 1 のエピソード約 2400 × 成功 0.73。概算)。容量 16384 は約 9 iteration で入れ替わる。段 0 は台本の 128 形のまま固定 (段 0 の成功は v7 で 0.97、v11 で 0.99 あり、形の種類を増やす必要は薄い)。

## 検討して採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 同じ p-data の保存の数に上限 | ループを断たない (上限に達した後は 2 番目・3 番目に苦手な形が埋める)。偏りは同じ p-data の中の幾何にも及ぶ (it650 のアーカイブの表の形は 6 手以内の成功 0.238、it300 のアーカイブでは同じ方策で 0.400) ので、p-data で数える上限では止まらない。上限の値という新しい調整の値が要る |
| 段が変わった手 (上がった手と下がった手) の後の形だけ保存 | ループは断つが、段 0 に入るのが「下がった手の後の形」(失敗の形) だけになる。v7 の段の定義では行き止まりの形も段 0 に入る。段 1 にも段 2 から崩れた形が入る |
| p-data ごとに均等に引く (Go-Explore の cell の選び方) | ループを断たない (引くときにならすだけ)。it650 の段 2 の 99 種類の p-data の多くは交差 5〜9 個のまれな形で、均等に引くとそれを引きすぎ、chain 評価の分布からずれる |
| 学習の進み具合で優先して引く (Prioritized Level Replay) | 単独ではループを断たない。形ごとの成功の集計・古さの扱い・混ぜる割合など調整の値が多く、1 版 1 変数で効果を読めない。v12 の後の候補 |
| 段が変わらない手 (`same_shape`) だけ保存しない | 形を変えても段に留まる手 (A -> A') の流れが残る |
| 古い順に捨てる代わりに、履歴から一様に残す (reservoir sampling) | 流れ込みの比率が同じなのでループは残る。古い方策の形も残る |
| 段 2 の表に無い形 (ラダー 2) も −1 にする | v7 の段 2 の 28〜48% を外す。v10 のような段 1 -> 段 2 の詰まりのおそれ ([0024](0024-v11-dead-end-stages.md) で退けた) |
| 時間切れに罰を与える | 保存の規則はそのままなのでループは残る。報酬を変える別の変数 |

## 実装の見通し (推奨。今のコードで確かめた)

- **保存する行を選ぶ関数を純 torch で足す** (`kt/common/state_archive.py`。isaaclab を import しない置き場所なので単体テストできる)。例: `rows_to_save(ok, before, after, rule)`。`rule` は `"every_move"` (今) と `"stage_up"` (v12)。`"stage_up"` は `ok & (after > before) & (after >= 1) & (after <= 2)`。テストは `tests/test_state_archive.py` に足す (0 -> 1・1 -> 2・0 -> 2 は保存、0 -> 0・2 -> 2・2 -> 1・1 -> 0・2 -> 3・−1 は保存しない、`ok` が偽なら保存しない、`every_move` は今の挙動と同じ)。
- **保存の項に引数を足す** (`kt/common/mdp/archive.py:461` の `record_stage_archive` と `:367` の `ResetToStage.record`)。`save_on: str = "every_move"` を足し、既定は今の挙動 (過去の版の挙動を変えない。`.claude/rules/mdp.md` の「項は追加だけ」)。`"stage_up"` のときは、手の前後の段を `kt/common/mdp/stages.py:62` の `stage_transition(env, action_name, rope_cfg)` から読む (`before` / `after`。同じ env ステップの中ではキャッシュされ、段の定義は `stage_function` と同じ)。`action_name` の引数 (既定 `"pick_place"`) も足す。手の後の段は `record` が今計算している値と同じになるはずなので、食い違えば検算として数える。
- **写しの引数を足す**: `history_every: int = 0` (env ステップ。0 なら書かない)。`{log_dir}/archive_history/archive_step{N}.pt` に書く (1 つ約 17 MB。200 env ステップ = 50 iteration ごとなら 300 iteration で 6 つ)。
- **版**: `versions/v12/` は v7 を継承し、`__post_init__` で `self.rewards.record_stage_archive.params["save_on"] = "stage_up"` と `["history_every"] = 200` だけを書く。Play (chain) の保存の規則は評価に効かない (アーカイブから引かず、ファイルにも書かない)。ただし Play は `log_dir` を学習の run のフォルダにするので、v12 の `play_post_init` は v7 の `play_post_init` の後に `history_every` を 0 にする (しないと学習が残した写しを評価が上書きする)。`tests/test_v12_cfg.py` で v7 との差がそれだけであることを静的に検査する (`tests/test_v11_cfg.py` が手本)。
- **ログ**: 今の `Curriculum/stage_log/arc_size_s{k}` に加えて、手ごとに保存した件数を段ごとに数えると、段 0 に何も入らないことと、段 1・2 の入れ替わりの速さが学習ログで見える (`ResetToStage.pop_stats` に `saved_s{k}` を足す)。
- **スモークテストで確かめる**: `params/env.yaml` の `save_on: stage_up`、段 0 の `arc_size_s0` が 128 のまま、`saved_s0` が 0、`restore_mismatch` 0。

## 外れたら仮説が誤りと言える予想

- 段 2 のアーカイブで 1 つの p-data が占める割合が、iteration 300 まで 20% を超えない (v7 の it100 で 17%)。`history_every` の写しを `view_archive.py --dump_pdata` で数える。
- 学習ログの段 2 の成功が、v11 s43 のように途中で半分以下に落ちない。段 0 の時間切れ (`timeout_s0`) が v7 の延長のように増えない。
- chain 評価が it100 -> it300 で下がらない (v7 s43 は 53.7% -> 39.3%、v11 s43 は 47.1% -> 40.0%)。
