- 状態: 有効 (v16 以降。2026-10-15 にユーザーが決めた。2026-10-16 に bootstrap の修正 ([0028](0028-v15-timeout-bootstrap-fix.md)) と番号を入れ替え、v15 → v16。**実装は v15 の結果を見てから**)
- 読むべき状況: v16 を実装するとき。ロープの直径・長さの env ごとの割り当てを扱うとき
- 最終更新: 2026-10-15

## 決定 (案)

v16 = 継承元 (v14 または v15。**v15 の結果が出てから決める**。v15 = v14 または v13 + 時間切れの bootstrap の修正) + **ロープの直径と長さを env ごとに振る** (ユーザーの指示、2026-10-14。範囲は下の「決めたこと」)。

- PhysX は実行中にカプセルの形を変えられない。直径・長さの違う USD を複数作り、起動時に env ごとに 1 つ割り当てる。env の寸法は run の間変わらない (reset で引き直す v14 の物理の DR とは違う)。
- リンク数 28 は変えない。長さは `capsule_half_length` (リンク間隔) の倍率、直径は `capsule_radius` の倍率で表す。
- v14 の物理の DR (6 軸)・critic の特権観測・段 0 の保存の規則は継ぐ。v14 の減衰比 ζ の範囲は ×1.0〜×2 ([0027](0027-v14-s0-reshape-dr-priv-critic.md))。
- critic の観測は 205 次元 (特権観測の物理 6 + 寸法 2 + policy 197)。actor の観測・行動・報酬は継承元のまま。
- 学習: seed 43 / 44、0 から iteration 300。比べる相手は継承元 (同じ seed)。公称の寸法での chain 評価と、寸法を振った評価で比べる。

## 調べて分かったこと (2026-10-15。コードを読んだ。実行はしていない)

### 直径と長さを 1 つの数で持つ箇所 (env ごとの値にする必要がある)

| 何 | 場所 | どう使われるか |
|---|---|---|
| 寸法を設定に流す | `kt/common/rope_task_cfg.py:93-94, 117-118` | `spec.rope_length` / `spec.diameter` を行動の設定と、`rope_diameter` を params に持つ項すべてに書く |
| 行動 | `kt/common/mdp/actions.py:128-133, 632-651` | 置き先の上限 `drop_xy_rel_frac × rope_length`、`drop_z_diameters × diameter`、`clear_diameters × diameter`、`near` |
| 床に落ちた判定 | `kt/common/mdp/rewards.py`、`terminations.py:116`、`archive.py`、`stages.py` | `settled_height_diameters × rope_diameter` (引数の既定 0.02) |
| フェーズの尺 | `kt/common/mdp/phases.py:220-226` | `drop_z_diameters`・`clear_diameters` (直径の倍数) |
| 指の握る力 | `kt/common/rope_model/rope_specs.py:316-321` | `k = 1500 × link_mass / radius` を指のゲインにする。v14 は公称の質量に固定 |
| 接触の設定 | `kt/common/rope_model/rope_cfg.py` | `contact_offset = 0.4 × 半径`・`max_depenetration_velocity = 0.4 × 半径 × 240`。**USD の spawn の設定なので、寸法ごとの `UsdFileCfg` が持てば env ごとに変わる** |

### 寸法に依らない箇所

- 位相 (`kt/common/topology/`) は xy への射影と線分の交差だけで、直径・長さを使わない (`DEFAULT_EPS` = 1e-12 のみ)。
- `RandomizeRopePhysics` (`kt/common/mdp/rope_dr.py`) は、剛性・減衰・質量・慣性・摩擦の公称値を env ごとに `clone()` で持つ (`_k0[ids]`、`_mass0[ids]` ...)。env ごとに寸法が違っても、公称値は env ごとの値のまま倍率が掛かる。**ただし摩擦の公称値の表示だけ env 0 を読む** (ログの表示のみ)。

### 観測はメートルのまま

`rope_link_positions` は env 原点相対の座標 [m] で、長さで割っていない (`kt/common/mdp/observations.py:85-96`)。actor には絶対の大きさが見える。寸法が ±25% 変わると観測の値の範囲も変わる。方策がそれに頑健になるかは学習しないと分からない。観測を長さで正規化すると、方策が寸法を知らないまま動けるが、v16 の変更が 1 つ増える。

### アーカイブの復元は寸法を考えていない

保存は root の姿勢 (xy は重心からの相対 [m]、z は env 原点から) と関節角 (`kt/common/state_archive.py`)。関節角は寸法に依らないが、root の相対位置は長さに比例し、z は半径に比例する。別の寸法の env に書き戻すと、重心が env 原点からずれ (ずれは、root と重心の公称の距離 × 長さの倍率の差。root がロープの端のリンクなら公称の全長が 1.14 m (28 リンク × 間隔 0.04 m + 0.06 m) なので、×1.25 の差で十数 cm と見積もれる。推測)、z が床にめり込むか浮く (半径 ±25% なので 2〜3 mm)。初期アーカイブ `outputs/archive_seed/overhand_28links.pt` は公称の寸法で作ってある (**上書きしない**)。

案: root の相対位置を、保存の時の env の寸法の倍率 (長さ・直径) で公称へ割り戻して持ち、復元のときに書き込み先の env の倍率を掛ける。既存のアーカイブは倍率 1 として読める。

### env ごとに違う USD を割り当てる方法

- Isaac Lab 2.3.0 に `sim_utils.MultiAssetSpawnerCfg` (`assets_cfg` に `UsdFileCfg` の列、`random_choice` で順番 / 乱数) がある (`isaaclab/sim/spawners/wrappers/`)。`random_choice=False` なら env の番号 % 個数で決まる。Articulation で使えるかは**未確認**。
- 全 USD で prim の階層・関節の名前と順序が同じである必要がある (`RandomizeRopePhysics` は DOF を名前の末尾 `:0/:1/:2` で分けている)。`generate_rope_usd.py` が同じ構造を作るので満たす見込み。
- `MultiAssetSpawnerCfg` の `rigid_props`・`collision_props` に値を入れると全アセットを上書きするので、`None` のままにして、各 `UsdFileCfg` の寸法ごとの `contact_offset` などを生かす。
- 複数アセットは `scene.replicate_physics=False` が要る見込み。4096 env での起動時間と学習速度への影響は**未確認** (現在の既定は True)。

## 決めたこと (ユーザー、2026-10-15)

1. **直径と長さの組: 格子で全部作り、ゲートで外す (案 C)。** 長さ・直径とも 3 水準 (3 × 3 = 9 組以内)。各組の USD を作り、skill `physics-check` のゲート 1 と 1 手あたりの発散率を組ごとに測り、通らない組は外す。閾値の数値は先に決めない。外した結果、実機の寸法に近い組が残らなければ、ユーザーと相談する。
   - 実機の紐は直径 **8 mm**・全長 1.02 m (ユーザー)。sim の公称は直径 20 mm・全長 1.14 m なので、実機は直径が ×0.4、長さが ×0.895。直径の ×0.8〜×1.25 には実機が入らないので、直径の範囲は下の「寸法の範囲」に変えた。
2. **観測は長さで正規化しない (そのまま)。** 変更を寸法の DR 1 つに絞る。方策が ±25% の大きさの違いを学習で吸収できるかを見る。足りなければ、公称の寸法で今と同じになる形 (位置を長さの倍率で割る) を別の版で足す。
3. **critic の特権観測に寸法 2 次元 (長さ・直径の倍率の log2 を範囲で [−1, 1] に) を足す。** critic の観測は 203 -> **205** 次元 (`rope_params` 6 + 2、policy 197)。v14 のチェックポイントからは再開できない (0 から学習する)。actor の観測は 197 次元のまま。
4. **握る力は指のゲインを公称のまま固定する** (v14 と同じ)。実機は位置サーボで、閉じる角度を紐に合わせて手で決めている。重くて太い組が握れない場合はゲートで落ち、その組を外すか範囲を狭める。

### 寸法の範囲 (ユーザー、2026-10-15)

実機の直径 8 mm は公称 (20 mm) の ×0.4 で、当初の範囲 (×0.8〜×1.25) の外にあるので、直径の範囲を実機を含むように変える。

| 軸 | 3 水準 (公称に対する倍率) | 実機 |
|---|---|---|
| 長さ | ×0.8 / ×1.0 / ×1.25 | ×0.895 (1.02 m) |
| 直径 | **×0.4 / ×0.63 / ×1.0** (8 mm / 12.6 mm / 20 mm) | ×0.4 (8 mm) |

- 太い側 (×1.25) は捨てる。公称 (×1.0) は直径の最大の水準になる。
- `half_length / radius` の比 (2.0 × 長さ / 直径) は、直径 ×1.0 で 1.6〜2.5、×0.63 で 2.5〜4.0、×0.4 で 4.0〜6.25。**比が小さい側の危険 (比 1.5 で NaN) は (長さ ×0.8、直径 ×1.0) の 1.6 だけ。細い側は比が大きく、リンクが細長い棒になる** (最も細い組は半長 20〜25 mm・直径 8 mm)。
- 細い組の懸念 (すべてゲートで確かめる。推測): リンクの慣性が小さく (`fine` の慣性は `simple` の 1/170 で、暴走した前例がある: `rope_cfg.py` の `MAX_ANGULAR_VELOCITY_DEG`)、最小曲げ半径 (直径の 2 倍 = 8〜16 mm) よりリンクの間隔の方が長いので結び目の分解能が粗い。握る力はゲインを固定するので、`k × 半径` (半径に比例) が直径に比例して下がるが、質量は直径の 2 乗に比例して下がるので、質量あたりの握力は上がる。
- 実機の組 (長さ ×0.895、直径 ×0.4) に最も近い格子点は (長さ ×0.8 または ×1.0、直径 ×0.4)。ゲートで落ちた場合は、ユーザーと相談する (直径の水準を足す、リンク数を変える版にする、など)。

## 実機の紐 (hiro_knot 側の記述)

- 実機の紐は全長 1.02 m・直径 8 mm (直径はユーザー、2026-10-15)。sim の 1.14 m に合わせるため、実機側の実行スクリプトが xy を約 1.12 倍している。太さ・重さ・摩擦の違いはそのままギャップに入る (`~/work/hiro_knot/docs/sim2real_plan.md:99`)。長さの倍率に直すと ×0.895 (範囲 ×0.8〜×1.25 の中)。

## 検討して採らなかった案 (暫定)

| 案 | 採らなかった理由 |
|---|---|
| reset のたびに寸法を引き直す | PhysX は実行中にカプセルの形を変えられない |
| スケールをシーンの USD の `xformOp:scale` で変える | 物理のカプセルの形・質量・関節の位置が合わなくなる (未確認。推測) |
| リンク数も振る | `RandomizeRopePhysics`・観測 (197 次元)・行動の `grasp_link_id` の範囲が変わる。v16 の範囲を超える |

## 実装の順序

1. (済み) 判断 1〜4 と寸法の範囲は「決めたこと」。
2. `rope_specs.py` に寸法違いのプリセットを足し (3 × 3 = 9 組。比の拘束はゲートで確かめる)、`generate_assets.py --rope <名前>` で USD を作る。既存の USD は上書きしない。
3. `MultiAssetSpawnerCfg` でロープを spawn できるか、Isaac Sim 上の小さなスクリプトで確かめる (28 リンクの Articulation が 4096 env で動くか、起動時間)。
4. 寸法を 1 つの数で持つ箇所 (上の表) を env ごとのテンソルにする。**既存の版の挙動は変えない** (v15 までは env 共通のスカラーのまま。新しい引数を足して既定は今まで通り)。
5. アーカイブの保存・復元に倍率を足す (上の案)。
6. skill `add-version` で `versions/v16/`。skill `physics-check` で、寸法の組ごとのゲート 1 と発散率。
7. スモークテスト、commit、学習。
