## 要約

- 結論: v3 の学習中の発散の約半分は PhysX の接触バッファのあふれ (b345065 で解消)。残りへの対策 (離す高さ 5〜10 cm・めり込み解消速度 0.4 m/s) は、乱数の手と学習済みの方策の計測で発散を 1/3〜1/4 に減らした。

## 結果

### 計測の方法 (`demos/divergence_bench.py`)

発散は行動と物理だけで決まり、エピソードの区切りや報酬には関係しないので、v3 の環境 (`Knot-v3`、
ソルバ反復 16) を基準にして、対策を `--cfg` で足したり外したりして比べた。

学習と同じ環境 (`gym.make`) で、1024 環境 x 24 手 = 24,576 手を打ち、1 手ごとに記録する。乱数の種を
固定すると結果は完全に再現する。

* **発散** は学習と同じ終了項 `diverged` (NaN・水平 3 m・高さ 5 m・リンク速度 20 m/s) が手の終わりに立ったもの。
* **どのフェーズで発散したか** は、手の途中でロープのリンク速度が初めて 20 m/s を超えたフェーズ
  (`PickPlaceActionCfg.diag=True` で記録)。
* **品質** (発散対策で結ぶ能力を落としていないか): 把持 (carry の終わりに掴んだリンクが 5 cm 以上上がって
  いる)、段が上がった手、交差が増えた手、手の後にロープが床に落ちているか、紐どうしのめり込みの深さ。
* 行動は 3 通り: 一様乱数 + まっすぐなロープ (学習の序盤に近い)、一様乱数 + ゲート 1 の台本の途中状態から
  (結び目の近く)、v3 の学習済み方策 `model_150.pt` を std でサンプル + アーカイブ 0.5 (学習の終盤に近い)。

```bash
V5='grasp_limits.release_tip_z=(0.05,0.10);scene.rope.spawn.rigid_props.max_depenetration_velocity=0.4'
uv run python -u src/isaac_twisted_rl/tasks/knot_tying/demos/divergence_bench.py --task Isaac-Twisted-RL-Knot-v3 \
    --num_envs 1024 --steps 24 --headless --archive_prob 0.0 --cfg "$V5"   # 乱数・まっすぐ
... --policy ckpt --checkpoint logs/rsl_rl/knot_tying_v3/2026-09-28_17-28-57/model_150.pt   # 学習済み方策
... --cfg 'grasp_limits.release_tip_z=(0.05,0.10);scene.rope.spawn.rigid_props.max_depenetration_velocity=0.3'  # 設定の切り分け
```

### 1. v3 の学習中の発散の半分は、PhysX の接触バッファのあふれだった (b345065 で解消済み)

同じ方策 (`model_150.pt`)・同じ種で、4096 環境 x 12 手を比べた:

| | 旧バッファ (b345065 より前) | 新バッファ (b345065) |
|---|---|---|
| PhysX の "Patch buffer overflow" | 1557 回 | 0 回 |
| 1 手あたりの発散 | 4.55% | **2.20%** |
| 発散で終わったエピソード | 41.0% | 20.6% |
| 固結びで終わったエピソード | 27.8% | **42.1%** |
| 発散が始まったフェーズ | lift が 53% | descend 26% / carry 27% / close 18% |

バッファがあふれると接触が黙って捨てられ、指とロープの接触が消えて lift で発散していた。
v3 の run (`2026-09-28_17-28-57`) の 1 手 6% は、この分を含む。b345065 の後に同じチェックポイントから
再開した run (`2026-09-30_19-54-58`) の 1 iteration 目も、1 手あたり 1.95% だった。
**b345065 より前の v3 の学習ログと比べるときは、この差を発散対策の効果と取り違えないこと**。

### 2. 残りの発散の内訳 (新バッファ、v3 の設定)

| 最初に 20 m/s を超えたフェーズ | 乱数・まっすぐ (発散 1142 手) | `model_150.pt` (発散 462 手) |
|---|---|---|
| descend / close (指を降ろして閉じる) | 94 (8%) | 258 (56%) |
| carry (運ぶ) | 242 (21%) | 96 (21%) |
| lower / release / settle_out (降ろして離す) | 737 (65%) | 58 (13%) |
| その他 | 69 | 50 |

* **離す高さ**: 乱数の手では、離すときの指先が床上 2〜12 mm だと 8.6%、42 mm 以上だと 2.6% 発散した。
  学習済み方策は、学習の中で既に 86% の手を最も高い位置 (52〜62 mm) で離すようになっていた。
* **指の真下の紐**: 掴むときに、開いた指の真下に別の紐に乗った紐があると発散しやすい
  (`model_150.pt` で、紐なし 0.8% に対して 3〜11%)。学習済み方策は結び目の近くを掴むことが多く、
  手の 27% がこれに当たる。
* **運搬**: 運ぶ距離が長いほど carry で発散する (A を入れた乱数の手で、0.2 m 以下 0.45%、0.5 m 以上 2.8〜3.0%)。carry を 0.6 -> 0.9 s に
  延ばしても 1 割しか減らなかったので、速さではなく、引きずる紐が自分自身と擦れることが主因と考えられる (解釈)。
* ハンドが開いた直後に横へ瞬間移動する `clear` (尺 0) は、どの条件でも発散 0〜1 手で、問題ではなかった。

### 3. 試した対策 (1 手あたりの発散。括弧内は品質)

乱数・まっすぐ (基準 4.65%、把持 98.7%、段が上がった手 21.2%):

| 対策 | 発散 | 把持 | 段が上がった手 | 1 step の時間 | 採否 |
|---|---|---|---|---|---|
| A: 離す高さを 5〜10 cm | 2.00% | 98.5% | 21.8% | 同じ | **採用** |
| A + 掴む高さを指の下の紐に合わせて止める (C) | 1.53% | 92.8% | 20.6% | 同じ | 不採用 (下記) |
| A + carry 0.6 -> 0.9 s | 1.87% | 98.6% | 21.5% | +8% | 不採用 (効果が小さい) |
| A + ロープの contact offset 4 -> 8 mm | 1.61% | 98.6% | 21.3% | +17% | 不採用 (遅い。4096 環境で接触バッファも増える) |
| A + ソルバの位置反復 16 -> 8 | 2.66% | 99.3% | 21.7% | −40% | 不採用 (乱数の手では発散が増える) |
| A + めり込み解消速度 0.5 m/s | 1.53% | 98.8% | 21.9% | 同じ | |
| **A + めり込み解消速度 0.4 m/s (v5)** | **1.44%** | 99.1% | 21.8% | 同じ | **採用** |
| A + めり込み解消速度 0.3 m/s | 0.87% | 99.0% | 21.6% | 同じ | 不採用 (下記) |
| A + めり込み解消速度 0.25 / 0.2 / 0.1 m/s | 0.65 / 0.34 / 0.02% | 95.6 / 50.8 / 0.9% | 20.9 / 13.3 / 0.5% | | 把持が壊れる |

`model_150.pt` (基準 1.88%、把持 95.3%、エピソードの 41.9% が固結びで終了):

| 対策 | 発散 | 発散で終わったエピソード | 固結びで終わったエピソード | 把持 | 段 2 -> 3 (1 手あたり) |
|---|---|---|---|---|---|
| A | 1.82% | 16.5% | 41.7% | 95.4% | 16.1% |
| C (浮いた紐の上で止める。A なし) | 0.53% | 6.1% | 12.4% | 41.8% | 1.9% |
| A + ソルバの位置反復 8 | 1.09% | 10.7% | 39.7% | 97.8% | 14.8% |
| A + めり込み解消速度 0.5 | 0.65% | 6.1% | 48.3% | 96.9% | 17.6% |

紐どうしのめり込み (手の後、リンク番号が 2 以上離れたカプセルの軸の最短距離から計算) は、0.4 でも
0.3 でも A だけの場合と変わらなかった (`model_150.pt`: 99 パーセンタイル 12.3 mm -> 12.4 / 12.2 mm)。
めり込み解消を遅くしても、紐が自分をすり抜けるようにはなっていない。

#### 掴む高さの対策 (C) を入れなかった理由

開いた指の真下に紐があると、指を降ろしたときにその紐を押し潰して発散する (上の 2)。そこで指の真下の紐
(`finger_footprint_top`) の上で指を止める対策を 3 通り試したが、どれも把持を大きく壊した:

* 掴むリンクの高さに合わせる: 浮いたリンクで把持が 99.6% -> 7.1%。指先がリンクの下端のすぐ下にしか
  来ないので、閉じる途中でリンクが下へ抜ける。
* 別の紐に乗った紐だけを避ける: `model_150.pt` の手の 58% がこれに当たり、その把持がほぼ全部失敗した
  (全体で 41.8%)。1 cm まで押し込むのを許しても 51.6%。結び目の近くでは、掴みたいリンクの横を別の紐が
  跨いでいるのが普通で、指をその紐より下へ入れないと掴めない。

めり込み解消速度を下げると、同じ手の発散 (descend / close) が 258 -> 34 手に減り、把持も壊れないので、
こちらで置き換えた。

#### めり込み解消速度をいくつにするか

下げるほど発散は減るが、0.25 m/s で把持が落ち始め、0.2 m/s では半分が失敗する。指は close フェーズで
片側 0.15 m/s 前後で閉じるので、ロープのめり込み解消がそれより遅いと、指がロープに食い込んだまま
摩擦で保持できなくなる (解釈)。0.3 m/s は把持の統計では問題が出ないが、ゲート 1 の台本の再生では固結びが
減った (下の表)。余裕を取って **0.4 m/s** にした。

### 4. ゲート 1 の台本の再生 (結ぶ能力が落ちていないか)

`demos/overhand_script.py --replay_actions`、256 環境 x 種 2 通り、±25% 揺らし。v3 以降のタスクは固結びや段の変化で
終了して reset されるので (スクリプトは reset を「発散」と数える)、終了しない `Knot-v2-R2` に v3 の尺と
置き先の範囲を入れて再生し、v5 の違いは `--cfg` で足した。

| | 固結び (512 中) | 発散 |
|---|---|---|
| v3 の設定 | 272 (53.1%) | 42 (8.2%) |
| A | 316 (61.7%) | 23 (4.5%) |
| A + めり込み解消速度 0.3 | 254 (49.6%) | 3 (0.6%) |
| **A + めり込み解消速度 0.4 (v5)** | **302 (59.0%)** | **7 (1.4%)** |

v5 の設定では、台本の手が高いところで離すように変わる (置く高さが 5 cm にクリップされる) が、それでも
固結びは v3 より多くできた。

## 結論

- 分かった: v3 の学習中の発散の約半分は PhysX の接触バッファのあふれ (b345065 で解消)。残りは、乱数の手では離す手 (lower / release / settle_out) が 65%、学習済み方策では指を降ろして閉じる手 (descend / close) が 56%。離す高さ 5〜10 cm (A) とめり込み解消速度 0.4 m/s で、乱数の手の発散は 4.65% -> 1.44%、学習済み方策では 1.88% -> 0.44% に減り、把持と固結びは落ちなかった (台本の再生では 53.1% -> 59.0%)。
- 推測 (転記元の「解釈」): 運搬中の発散は、速さではなく引きずる紐が自分自身と擦れることが主因。0.25 m/s 以下で把持が壊れるのは、指が閉じる速さ (片側 0.15 m/s 前後) よりめり込み解消が遅いため。
- 未確認: 計測の種の値と出力のパス。**この計測は学習済みの v3 方策と乱数の手で測ったもので、ゼロからの学習での効果は測っていない。** その後の学習では 0.4 m/s が段 2 -> 固結びの学習を止めた (v5 README の「学習の結果」、[`2026-10-01_v4-v6_overnight_detail.md`](2026-10-01_v4-v6_overnight_detail.md) の追記)。
