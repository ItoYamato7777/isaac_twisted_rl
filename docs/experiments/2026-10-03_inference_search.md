2. **同じ状態・同じ手でも、手の後の段は 3 割ほど変わる。** 複製元と複製の一致率 (73%) と複製どうしの一致率 (71%) が

### ビーム探索の要点 (詳細は `scripts/rsl_rl/README.md`)

| 項目 | 決めた内容 | 理由 |
|---|---|---|
| 問題 | まっすぐなロープから固結びまで。すべての問題が同じ初期状態 | 論文の「同じ問題を複数 seed」と同じ形 |
| 並列化 | 環境を 16 個ずつの枠に分け、32 問題を並列。終わった枠で次の問題を始める | GPU を常に使い切る |
| 1 ラウンド | フロンティア (最大 4 ノード) に 16 環境を割り振って複製 -> 1 手 -> 分類 | ご依頼の流れのまま |
| 候補の行動 | std 付きでサンプル。各ノードの最初の 1 環境だけ平均の行動 | 決定論的方策の手も必ず試す |
| 分類 | 固結び = 成功、発散・段が下がる・吊ったまま段が変わる = 捨てる、段が上がる = 優先、同じ = V(s) で順位付け | ご依頼のまま。吊ったままの段は確定しないので捨てる |
| 選別 | 段の高い候補を先に取り、**同じ段の中だけ** その段の critic の V(s) で比べる | 段ごとの critic は別のネットワーク |
| 線の打ち切り | 同じ段のまま 6 手続いた線は捨てる | 学習の 1 遷移の上限 (6 手) を超えた状況を方策は知らない |
| 再開 | フロンティアが尽きたら、到達木から重み `(1−p) x 段 / (1 + 再開回数)` + `p x 一様` (p = 0.05) で 4 ノード | TWISTED の「交差数に比例 + 確率 p でランダム」。段を交差数の代わりに使う |
| 予算 | 問題ごとのシミュレートした手数 (1 ラウンド 16 手、固結びが出たラウンドも全部数える)。実時間の打ち切りも可 | 並列に試した候補は全部シミュレートしているため |

### 状態の複製で写すもの

ロープ (root の姿勢・重心速度・関節角・関節速度)、グリッパー (root の姿勢・速度、指の関節角・速度・目標値)、

| 20〜30 分 | 約 420〜630 手 (512 手の列) | 100% / 100% | 100% / 97〜100% | 94% / 88〜98% |

GPU を占有すれば 1 ラウンドは短くなり (v5 の探索は cuda:1 で 12.5〜45 秒と負荷で大きく変わった)、同じ実時間で使える手数は増える。
**論文の「30 分」に当たる予算では、v4 と v6 は固結び (3 交差) をほぼ確実に結べる。** 論文の 3-Medium 44% などは別の結び目の
問題集なので、数字を直接は比べられない。

## 4. 結果からわかること

### 4.1 探索を入れても版の順位は変わらず、差は広がった (今回の 1 シードずつの範囲で)

v4 と v6 s42 の差は、決定論的な chain 評価 3.7 ポイント (41.6% 対 37.9%) -> 確率的な chain 評価 7 ポイント -> best-of-N
(64 手) 15 ポイント -> ビーム探索 (64 手) 34〜37 ポイントと、探索を強くするほど広がった。最初の固結びまでの手数の期待値でも
v4 は v6 s42 の 2/3 (39 手対 59 手)。

v4 は確率的な方策で 27% のエピソードが発散するが、発散で失う手は全体の 20% で、残りの手で固結びに届く率が高い
(1 本の固結び率 33% 対 26%、到達した解の手数 3.5 対 4.6)。v6 は発散が少ない代わりに時間切れ (段 2 で手を使い切る) が
64% あり、探索でもその分の手がかかる。**「発散は捨てるだけなので v4 が有利になる」という見込みは、v4 については
当たった** (解釈)。

### 4.2 ただし版の差としてはまだ結論を出せない

* 各版 1 シード。v6 の 2 シードは chain 評価で 15 ポイント離れ、ビーム探索 (途中) でも 64 手で s42 52〜56%、
  s43 44〜69% と幅がある。v4 と v6 の差がシード差を超えるかは、v4 の 2 本目のシードと v6 s43 の rollouts が要る。
* v5 は (a)〜(c) のどれでも最下位で、差 (best-of-N 64 手で v6 s42 の 4 割) はシード差よりずっと大きい。めり込み解消速度
  0.4 m/s で段 2 -> 固結びを学べなかった版 (`versions/v6/Result_Report_v6.md`) が、探索でも補えなかったと読める (解釈)。

### 4.3 V8 の土台 (v6 か v7 か) はまだ決められない

v7 (= v6 + めり込み解消速度 0.96 m/s、v4 と同じ物理) は評価できていない。v4 の結果は「発散は多いが段 2 が強い」方策が
探索で有利になることを示しているので、同じ物理の v7 も v6 より探索で伸びる可能性がある (解釈。v7 は観測に次にたどる辺を
持ち、離す高さが v6 のまま、iteration 70 という違いもあり、v4 の結果から推すことはできない)。**§6 の 1 を先に行うこと。**

### 4.4 今の設定のビーム探索は best-of-N をはっきりとは上回らない

* 128 手以上ではビーム探索が少し上 (v6 s42 93〜96% 対 89%、v5 56〜66% 対 50%、v4 98% 対 97%)。
* 64 手以下では、1 ラウンド 16 手の刻みが効く。best-of-N は 1 本の展開で 10 手前後で結べることがあるのに対し、ビーム探索は
  深さ 1 ごとに 16 手を払う。v6 s42 の 64 手はビーム 52〜56% 対 best-of-N 67% で逆転した。
* 同じ状態・同じ手でも結果が 3 割変わる (§3.1) ので、1 ノードから 4 本の候補を出す程度の分岐は、best-of-N の独立な展開と
  比べて得が小さい、と考えられる (解釈)。V(s) による順位付けが効いているかは、ランダムな順位付けとの比較 (§6) で確かめていない。

## 5. 注意・未確認の点

* 評価は途中で止めた (§2.3)。v5 / v6 のビーム探索の値は途中の run の下限〜上限で、v6 s43 の rollouts と v7 は未実施。
* 各版 1 シード。チェックポイントは v4〜v6 が iteration 100、v7 が 70 で揃っていない (v7 の run は 70 で止めたため)。
* GPU を別のセッションの評価と共有した。成功率と手数には影響しないが、実時間の換算 (§3.6) は負荷で 3 倍ほど変わる。
* ビーム探索の成功率はラウンド単位 (16 手) で数えるので、16 手より細かい予算では悲観的に出る。best-of-N は 1 本ずつ逐次に
  打つ勘定で、成功した時点で止められる分だけ有利な数え方 (`scripts/rsl_rl/README.md`)。
* 探索の設定 (フロンティア 4、1 ノード 4 候補、同じ段 6 手で打ち切り、再開の p = 0.05、各ノードの最初の候補を平均の行動に)
  は 1 通りしか試していない。
