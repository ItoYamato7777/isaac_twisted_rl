### 測り方

- `rollouts` と `search` は前の記録と同じ設定 (付録のコマンド)。`search` は 512 環境 = 32 問題 x 16 環境、フロンティア 4、128 問題、予算 1024 手 / 問題、平均の行動を各ノードの最初の候補に、V(s) で順位付け、`--max_minutes 120`。
- `shapes` (今回足したモード。アルゴリズムは [`scripts/rsl_rl/README.md`](../../src/isaac_twisted_rl/scripts/rsl_rl/README.md) の「形ごとの切り分け」): 段 2 のアーカイブの形を 1 つずつ 64 環境に**同じ初期状態** (重心を原点へ、速度 0、yaw 0) で書き込み、**決定論的な方策** (平均の行動) で 6 手 (学習の 1 遷移) 打つ。試行の違いは物理の非決定性だけ。Play (chain モード) のままなので段が下がっても続ける。形は 2 通り:

- 書き込んだ後の段が 2 でない形は集計から外す仕組みだが、4 本とも 0 形だった (どの形も 64 環境すべてで段 2)。

## 結論

- 分かった:
  1. **v7 に探索を付けると、ほぼ確実に固結びに届く。** 予算 128 手で best-of-N 95.6% / 91.8%、ビーム探索 94.5% / 99.2%。予算 1024 手ではビーム探索が 128 問題すべてを解いた。この run の処理速度 (約 26 手/分/問題) で、128 手は約 5 分。前の記録の v4 (best-of-N 128 手で 96.7%) と同じ水準。
  2. **学習中に方策が段 2 に着いた形では、成功率が形で大きく違う。** 成功の分散の約半分 (0.49 / 0.51) が形の間の違いで説明できる。全形で同じ成功率なら 0% のはずの「64 回とも失敗」「64 回とも成功」の形が、それぞれ 9〜13% と 5〜7% ある。2 シードで同じ形になった。
  3. **残りの約半分は、同じ形・同じ行動でも結果が変わる物理のばらつき。** 成功率 0.2〜0.8 の形が 27% あり、決定論的な方策なのに 64 回の結果が分かれる。
  4. **学習中に到達した形は低いほうに偏っている** (形の約半分が成功率 0.2 未満、平均 0.27〜0.29)。失敗の多くは段が下がる手 (試行の 60〜65%) で、発散は 4% だけ。
  5. **台本の初期アーカイブの形は易しい** (平均 0.92〜0.95、87% の形が 64 回とも成功、1 手目で 9 割)。同じ p-data (cover の後の形) でも、学習中に到達した形は 0.27 に留まる。成功を分けているのは位相 (p-data) ではなく幾何。
  6. 確率的な方策の chain 評価 (30.9% / 27.7%) は、決定論的 (53.7% / 47.3%) より 20 ポイント以上低い。前の記録の v4 / v6 と同じ向き。
- 推測:
  - 段 2 -> 固結びの詰まりは、学習量の不足よりも、**方策が段 2 に作る形が tuck しにくい形に偏っていること**が大きい。段 2 から始める回数を増やした v9 が chain 評価で v7 を上回らなかったこととも合う ([`2026-10-05_v9_stage2-weight.md`](2026-10-05_v9_stage2-weight.md))。段 1 -> 2 の手 (cover) が、段 2 に入ればよいだけで、次の tuck のしやすさを見ていないのかもしれない (確かめていない)。
  - 推論時探索が効くのは、物理のばらつき (形の中のばらつき、約半分) を引き直せることと、段が下がった線を捨てて別の候補 (別の形の段 2) から続けられることの両方による。
- 未確認:
  - 学習中に到達した形 (`archive.pt`) は、学習の最後のリングバッファで、chain 評価で方策がまっすぐなロープから作る段 2 の形とは分布が違いうる。chain 評価で到達した段 2 の形で同じ診断はしていない。
  - yaw を 0 に揃えた。学習・chain 評価の形はランダムな yaw / まっすぐなロープからなので、yaw の違いが成功率に効くかは見ていない。
  - 確率的な方策での `shapes`、6 手より長い試行。
  - 形の幾何のどこ (たるみ・輪の大きさ・先端の位置など) が成功を分けるか。
  - 探索の設定の比較 (1 ラウンドの環境数 4 / 8、`--rank random`、`--no_mean_first`) は未着手。
