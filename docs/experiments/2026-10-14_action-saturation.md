# chain 評価が it70〜100 の後に下がる原因の調査: 方策の平均が行動の範囲の外へ出る (2026-10-14)

- 状態: 凍結
- 読むべき状況: v13 (方策の平均の範囲外の罰則) の根拠を知るとき。学習の途中で chain 評価が下がる・段の方策が崩れるとき

## 要約

- 結論: 全 run で、方策の平均が行動の範囲の外へ出る割合が学習とともに増えた。大きく崩れた run では段 0 の置き方のチャネルまで張り付いた。相関のみ。v13 ([0026](../decisions/0026-v13-action-bounds-loss.md)) の根拠。
- 有効か: 計測は有効。崩れの原因の候補としては弱まった: v13 で罰則を入れても同じ型に崩れた ([v13 の記録](2026-10-14_v13_bounds-loss.md))。今の最有力は時間切れの bootstrap の不具合 ([時間切れの bootstrap の記録](2026-10-15_timeout-bootstrap-and-stage2-bottleneck.md))。

## 目的と仮説

v7・v11・v12 のどれも、chain 評価の山が it70〜100 にあり、その後に下がる (v12 s44 は 58.8% -> 2.0%、v11 s43 は it300 の 40.0% -> it1000 の 7.6%)。
v12 でアーカイブのループを断っても下がったので、版の間に共通の原因があると考えた。

v12 s44 の手ごとの診断 ([2026-10-13_v12_archive-stage-up](2026-10-13_v12_archive-stage-up.md)) で、崩れた後の段 1・2 の行動 (クリップ後) の平均が
複数のチャネルで −1.0 / +1.0 ちょうどだった。仮説 (推測): actor の出力は線形で、環境 (`PickPlaceAction.process_actions`) が [−1, 1] に
クリップし、PPO の log prob はクリップ前の行動で計算する。平均が範囲の外へ出ると、標本の多くが同じ端の行動になり、その次元の違いが
報酬に現れなくなるので、平均を範囲の中へ戻す勾配が無い。平均は外へ流れ、方策は変化に付いていけなくなる。

## 結論

- 分かった:
  - 6 本の run のすべてで、方策の平均が行動の範囲 [−1, 1] の外にある割合は学習とともに増え続けた。段 0 が最も大きい (it300 で 37〜73%、v11 s43 の it1000 で 76%)。平均は最大で |平均| 14 まで出ていた。
  - grasp と Δlink は、chain 評価が崩れない run (v12 s43・v7 s43) でも段 0 で 76〜92% が範囲の外。
  - chain 評価が大きく崩れた 3 つ (v12 s44 の it100 以降、v11 s44 の it200 以降、v11 s43 の it1000) では、段 0 の置き方のチャネル (dx・release_z・yaw) も 50〜97% が範囲の外だった。崩れない v12 s43 の it300 は dx 12%・release_z 2%。
  - 段ごとの最小の std は、段 1 でどの run も 0.03〜0.06 まで下がった (崩れた run と崩れない run で差が無い)。
- 推測:
  - grasp と Δlink が範囲の外にあるのは「ロープの端を掴み、いちばん遠くへ置く」打ち方で、行動の端が本当に良い手になっているもので、害は小さい。
  - 置き方のチャネルまで範囲の外に張り付くと、その次元の勾配が無くなり、方策が段の間の分布の変化 (例: 段 0 の打ち方が変わる) に付いていけなくなる。これが崩れの共通の原因の最有力の候補。
- 未確認 (この記録だけでは原因と言えない理由):
  - 時期がきれいに重ならない。v12 s44 の it70 は dx がすでに 43% 範囲の外で、chain 評価は最高 (58.8%)。v11 s44 の it150 も 4 チャネルが範囲の外で 50.2%。崩れの閾値は決められない。
  - 相関だけで、因果は確かめていない。確かめるには平均を範囲の中に保って学習し直す (v13) 必要がある。
  - 観測はすべて v12 の rollout から取った。v7・v11 の方策自身が訪れる状態での値ではない。
