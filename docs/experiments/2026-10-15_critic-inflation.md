# 段 0 の critic の価値 V の膨らみと、段 0 の崩れの関係 (v7・v11・v12・v13 の事後調査) (2026-10-15)

- 状態: 凍結
- 読むべき状況: 段 0 が崩れる原因を考えるとき。critic・時間切れの bootstrap・次の版 (v13 の次の手) を決めるとき。学習ログの `Loss/value_mean_s*`・`Loss/value_over_s*` の読み方を知るとき

## 要約

- 結論: 段 0 が崩れた 4 本の run は段 0 の V の平均が 1/γ を超えて 2〜15 まで膨らみ、崩れなかった 3 本は最大 1.05。V の膨らみと段 0 の時間切れの増加は 10〜40 iteration の範囲で重なる。
- 有効か: 計測は有効。結論の推測「時間切れの bootstrap だけでは膨らまない」は誤り (冒頭の注記)。膨らむ原因は、後の調査で時間切れの bootstrap の不具合とされた ([時間切れの bootstrap の記録](2026-10-15_timeout-bootstrap-and-stage2-bottleneck.md)。因果は未確認)。V は v12 の rollout の固定した観測での値で、各 run の学習の分布での値ではない。

> **注記 (2026-10-15、後で分かったこと)**: 「結論」の推測の「時間切れの bootstrap だけでは膨らまない見込み (r ≤ 0 なので不動点は 0 以下)」は誤り。
> 6 手目に段が上がった手では時間切れ (`truncated`) と段の上昇 (`terminated`) が同時に立ち、PPO は `terminated` を見ずに
> γ·V(s) を足すので、その手の目標は 1 + γ·V(s) になる (r = +1 の手も bootstrap される)。6 手目にだけ訪れる状態での不動点は
> p/(1 − γ) (上限 20) で、ここで測った 2〜15 はこの範囲に入る。崩れた v12 s44 it150 の方策は、まっすぐなロープから 512 環境中
> 490 で、ちょうど 6 手目に段 0 を上げていた。同じ理由で、「次の作業」の案 B・C は 6 手目に上げる得 (目標 1 + γ·1) を残す。
> 詳細は [2026-10-15_timeout-bootstrap-and-stage2-bottleneck](2026-10-15_timeout-bootstrap-and-stage2-bottleneck.md)。本文は書き換えていない。

## 目的と仮説

v13 は PPO の損失に平均の範囲外の罰則を足したが、範囲の外に出る割合は減らず、s44 は v12 s44 と同じ型に段 0 から崩れた
([2026-10-14_v13_bounds-loss](2026-10-14_v13_bounds-loss.md))。v13 の学習ログを読むと、崩れた run だけ価値関数の損失が増えていた。
そこで critic の価値 V を調べた。

段 0 で正の報酬は段を上げたときの +1 だけで、ほかは 0 か負 (`transition` の +1 / 0 / −1、`grasp_shaping`・`failure`・`held_up` は ≤ 0) なので、
**段 0 の V は 1 を超えないはず**である。時間切れ (6 手) は `time_out=True` で、PPO は時間切れの手の報酬に `γ·V(その手を打った状態)` を足す
(`rsl_rl/algorithms/ppo.py` の `process_env_step`)。γ = 0.95 (`params/agent.yaml`) なので、V が `1/γ ≈ 1.053` を超えると、
時間切れの手の報酬 (γ·V) が段を上げる手の報酬 (+1) を上回る。

仮説: **段 0 が崩れる run では、段 0 の V が 1/γ を超えて膨らむ。崩れない run では超えない。**
外れたら仮説が誤りと言える予想: (1) 崩れた run の段 0 の V の平均が 1/γ を超えない、(2) 崩れない run の段 0 の V の平均が 1/γ を超える。

**これは探索的な調査である**: 予想は v13 の学習ログの価値関数の損失を見て気づいた後に置いた (見る前に置いた予想の確認ではない)。

## 結論

- 分かった:
  - **予想 (1)(2) は当たった** (この観測で、崩れた 4 本と崩れなかった 3 本について)。崩れた run は段 0 の V の平均が 1/γ = 1.053 を超え、2.3〜15.3 まで膨らんだ。崩れなかった run の全 checkpoint の最大は 1.00・0.97・1.05 (v11 s43 の it720 まで)。v7 s43 の延長は崩れの途中で、V が 1.14〜1.17。
  - V が 1/γ を超えた状態は、critic の誤差である (報酬の上限が +1 なので、正しい V は 1 を超えない)。
  - V の平均が上がる時期と段 0 の時間切れ (`timeout_s0`) が増える時期は、10〜40 iteration の範囲で重なる。v12 s44 と v13 s44 では V が先に上がり始めた。v11 s44 と v11 s43 の延長では、10 iteration の間隔では先後を分けられない。価値関数の損失の増加は V の膨らみより後で、損失の増加は崩れの原因ではなく結果と読める。
  - 時間切れの手の報酬は `γ·V(その手を打った状態)` (コードで確認)。V が 1/γ を超えた状態では、段を上げる手 (+1) より時間切れの手の方が critic の見積りの上では大きい。
  - 割合 (`over`) だけでは警報にならない。崩れていない run でも 0.3〜0.4 になる (v7 s44 の it70、v11 s43 の it250)。平均が 1.05 を超えて上がり続けるかが目印になる (この観測の値。学習ログの値で確かめていない)。
- 推測:
  - V が 1/γ を超えると、段を上げずに時間切れを待つ方が得になり、方策が段 0 で手を進めなくなる (崩れの原因が V の膨らみ)。これは相関と時間の順序 (v12 s44・v13 s44 で V が先) からの推測で、V を抑えた版で崩れが消えるかを確かめていない。
  - **(この項の「膨らまない見込み」は誤り。冒頭の注記を見る)** **V が膨らむ原因は分からない。** 時間切れの bootstrap だけでは膨らまない見込み: 時間切れの手の目標は `V(s) ← r + γ·V_old(s)` (done なので次の状態は使わない) で、γ < 1 の縮小写像であり、不動点は r/(1−γ) (r ≤ 0 なので 0 以下)。膨らませる別の原因 (関数近似の外挿、価値の clip、ほかの報酬) があるはず。
  - 一度膨らんだ V が戻らない理由も分からない (v11 s43 の延長は it760 から it1000 まで 6〜15 のまま)。時間切れの手の目標が縮小写像であることとも合わない。
- 未確認:
  - **学習中の訓練分布での V。** ここで数えたのは固定した観測 (v12 の rollout) での V で、各 run が学習で見る状態 (アーカイブから始まる段 0) での V ではない。崩れた方策に対して、その観測は分布の外 (外挿) である。自分の方策の観測 (v12 s44 it150) でも V は 5.3 だったので、外挿だけで説明できる値ではないが、学習の分布での値は学習ログ `Loss/value_mean_s0` (`BoundedPPO` を使う版。v14 の run には入っていない、次の版から) で測る。
  - V の膨らみが崩れの原因か結果か (因果)。
  - v14 (critic が特権観測を見る) で V の膨らみ方が変わるか。critic の入力が違うので、この観測では数えられない。学習ログの `timeout_s0`・価値関数の損失で見る。
  - v7 s43 の延長がこのまま崩れたか (model_330 で止まっている)。
