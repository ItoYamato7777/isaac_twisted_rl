# chain 評価が頭打ちになる原因の事後調査: 時間切れの bootstrap の不具合 (段 0 の崩れ) と段 2 の詰まり (頭打ち) (2026-10-15)

- 状態: 凍結
- 読むべき状況: 段 0 の崩れ・critic の V の膨らみの次の版を決めるとき。崩れない run でも chain 評価が 30〜50% で止まる理由を知るとき。チェックポイント 1 つの chain 評価の値をどこまで信じるかを決めるとき

## 目的と仮説

chain 評価の `knot` は最高でも 65.4% (v13 s44 の it70) で、多くの run は 30〜50% に留まり、it70〜100 の後に下がる。

(2) 崩れない run の頭打ち。学習も評価も新しく回していない (既存のログ・評価 JSON・手ごとの診断の保存を読んだ)。

## 結果

### 1. 時間切れの bootstrap の不具合 (コードを読んだ)

- Isaac Lab の `TerminationManager.compute` は、`time_out=True` の項を `truncated`、それ以外を `terminated` に別々に OR する (`.venv/lib/python3.11/site-packages/isaaclab/source/isaaclab/isaaclab/managers/termination_manager.py:164-170`)。6 手目に段が上がると両方が立つ。
- ラッパーは `extras["time_outs"] = truncated` を渡す (`.../isaaclab_rl/isaaclab_rl/rsl_rl/vecenv_wrapper.py:163`)。PPO は `time_outs` の手の報酬に、`terminated` かどうかを見ずに γ·V(s) を足す (`.venv/lib/python3.11/site-packages/rsl_rl/algorithms/ppo.py:161-164`)。V(s) はその手を打った状態の値。
- したがって 6 手目に段を上げた手の目標は 1 + γ·V(s)、6 手目に段が下がった・発散した手は −1 + γ·V(s) になる。
- v4 の `TerminationsCfg` の docstring (`versions/v4/env_cfg.py:125-130`) はこの重なりを知っていて、ログ (`ResetToStage`) が成功として数えるよう項の順を決めている。PPO の bootstrap には手当てが無い。v5 以降の版 (v14 を含む) はこの終了を継承している。
- 6 手目にだけ訪れる状態では V の不動点は p/(1 − γ) (p は 6 手目に上がる割合) で、上限は 20。崩れた run の段 0 の V (2.3〜15.3) はこの範囲に入る。

## 結論

- 分かった:
  - **B1 の不具合はコードにある。** 6 手目に段が上がる・下がる・発散した手では、時間切れも同時に立ち、PPO はその手の報酬に γ·V(s) を足す。[critic-inflation の記録](2026-10-15_critic-inflation.md) の「時間切れの bootstrap だけでは膨らまない (r ≤ 0)」は誤り (r = +1 の手も bootstrap される)。v14 を含む v4 以降のすべての版にある。
  - **崩れた v12 s44 it150 の方策は、まっすぐなロープから 512 環境中 490 で、ちょうど 6 手目に段 0 を上げた** (健全な v12 s43 は 512 / 512 が 1 手目)。報酬と終了の中で 6 手目に上げる手を得にするのは、この不具合だけ。待つのはまっすぐなロープから入った段 0 だけで、段 0 に入り直したときと段 1・2 には出ない。
  - 段ごとの 1 手の結果の割合だけのマルコフ連鎖で、18 手の knot と発散が 7 つのうち 6 つで 1〜4 ポイント以内に再現した。外れたのは v12 s44 it70 (模型 72.4%、実測 58.8%)。
  - 崩れない run の段 2 の 1 手は、固結び 8〜18%・段 1 への下降 25〜47%。v12 s43 it300 では段 2 に 90% が着くが、段 1 で平均 6.0 手を使い、段 1 で終わる時間切れと発散が合わせて 34% ある。
  - 隣り合うチェックポイントの `knot` の差は平均 9.0 ポイントで、二項の見積り (2.4) の約 4 倍。chain 評価は決定論的なので、この差は方策の変化による。崩れない run の「it70〜100 の後の下降」(v12 s43 は it100 38.7% → it300 39.8%、v11 s43 は 47.1% → 40.0%、v13 s43 は 35.5% → 27.7%) は、この揺れと同じ程度。
  - A2 は弱い: v12 s43 it300 で、段 1 の訪問あたりの上昇は初めて 0.62・上から落ちて 0.60、段 2 は初めて 0.23・下から入り直して 0.17。it100 では段 1 の差が大きかった (0.99 と 0.75)。
- 推測:
  - **B1 が段 0 の崩れの原因。** V(s) > 1/γ になると、1〜5 手目に段を上げる (目標 1) より、待って 6 手目に上げる (目標 1 + γ·V) ほうが得になり、6 手目に上げる遷移が増えて V をさらに押し上げる。まっすぐなロープは毎回同じ始まりなので、critic がそこからの「6 手目の状態」を見分けて V を p/(1 − γ) の側へ膨らませられる。介入 (修正した版の学習) では確かめていない。
  - 保留中の案のうち、B (bootstrap の V を 1 で頭打ち) と C (critic の出力を [−1, 1] に制限) では、6 手目に上げた手の目標は 1 + 0.95·1 = 1.95 のままで、待つ得が残る。A (時間切れを終端にする) か、`time_outs` を `truncated & ~terminated` にする修正なら待つ得が消える。
  - **崩れない run の頭打ちの主因は、段 2 の 1 手の成功の低さと下降の多さ** (模型の上)。段 2 を台本の形の 1 手目の水準にすると 18 手で 88%、発散を 0 にしても 45%、段 1 を it100 の水準にしても 50%。段 2 の成否は形 (幾何) で決まる割合が大きく、方策が作る形は台本の形よりずっと難しい ([推論時探索 v7 の記録](2026-10-06_inference_search_v7.md)) ので、段 1 が段 2 のどの形に上がっても +1 をもらう報酬 (A1) が効いている可能性がある。方策の手の分布の中に良い手があるのに平均の行動では選べない、という説明 (探索で解けることと合う) とは、この調査では分けられない。
  - 18 手の上限 (D1) は v12 s43 it300 で約 17 ポイントを削り (模型で 36 手 56%)、上限が無くても発散で 65% 前後に止まる (C1)。どちらも 90% に届かない理由の主因ではない。
  - 最高値の 65.4% と 58.8% には、多数のチェックポイントから最大を拾った効果が混ざっている。
  - v12 s44 it70 で模型が実測を 14 ポイント上回ったのは、段 1・2 の 1 手の結果が、どの手順で着いたかで違う (初めての訪問がよく、入り直しが悪い。上の表) ため。
- 未確認:
