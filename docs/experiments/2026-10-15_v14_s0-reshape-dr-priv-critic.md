## 結論

- 分かった:
  - **予想 1 は当たった。** 段 0 のアーカイブは it10 で容量に達し、`timeout_s0` は 2 シードとも iteration 0 の後は 0.1 を超えなかった (it50 以降の最大 0.022)。
  - **予想 2 は当たった (大きく上回った)。** 公称の物理での chain 評価の 2 シードの平均は、it100 で v13 +16 ポイント、it300 で +41 ポイント。v14 は 2 シードとも it300 で 0.57〜0.58 で、it70〜100 の後に下がらなかった。崩れなかった v13 s43 と比べても、it100〜300 のどの点でも 17〜35 ポイント上。
  - v14 の it300 の `knot` は、記録のある it300 の値 (v7〜v13) のどれより高い。v14 の it100 は v7 の it100 と同じ水準で、v14 は it100 の後も伸びた唯一の版。
  - **予想 3 は外れた。** DR を付けた評価での下がり幅は v14 (平均 −8 ポイント) の方が v13 (−1 ポイント) より大きい。v13 の方策は DR の物理で、4 点のうち 3 点で公称と同じか少し高かった。
  - v14 の評価では段 0 の時間切れ・発散・18 手の時間切れがどれも v13 より少なく、段 3 (固結び) に届く割合が 2 倍になった。
- 推測:
  - 公称の物理での差の主因は、段 0 の保存の規則 (段 0 の方策が交差の無い様々な形から練習できる) と見る。v13 の 2 シードの違い (s44 だけ段 0 で崩れた) と v14 の 2 シードがともに崩れないことは、段 0 の始まりの分布の狭さが崩れに関わることと合う。ただし DR・特権観測の効果と分けられていない。
  - DR の下がり幅が v13 で小さいのは、v13 の方策の公称の値が低く (0.06〜0.38)、物理の違いで失う手が少ないためかもしれない。DR の範囲の大部分 (ζ 以外の 5 軸の中ほど) は公称の物理とあまり違わず、v13 にとっても難しくない可能性もある。
  - 時間切れの bootstrap の不具合は v14 にもある。v14 で崩れなかったのは、不具合の効きを段 0 の始まりの多様さが弱めたためかもしれない (因果は未確認)。
- 未確認:
  - 3 つの変更のどれが効いたか (切り分けの run: `save_on=stage_up`・`rope_dr.params.enabled=false`・`obs_groups.critic=[policy]`)。
  - DR 付きの評価で、どの物理の軸で失敗するか (`eval_chain.py` は env ごとの倍率を JSON に残さない)。
  - it300 の後も伸びるか。
  - 段 0・段 1 から 1 手で固結びに達したエピソード (v14 s44 it100 で 2%・8%。v12・v13 の評価でも 1〜2%) が正しい判定か。
