# v17 の学習の前の確認 (尺の配線・速さ・発散・ゲート 1・スモークテスト) (2026-10-19)

- 状態: 凍結
- 読むべき状況: v17 の学習・評価の結果を読むとき。v17 の尺が意図どおり組み上がっているか、学習の前の発散と速さを知りたいとき

## 要約

- 結論: v17 の設定は、学習・Play とも意図どおりの尺 (1 手 591 物理ステップ、学習 6 手・Play 18 手) で組み上がった。4096 環境のランダムな行動で、1 手の時間は v15 の 0.766 倍、1 手あたりの発散は 3.76% (v15 は 3.36%)、ゲート 1 (学習の尺の台本) は 64/128 だった。この 3 つは 0030 の計測 (v14 の設定に D4 の尺を上書き) と同じ値か近い値で、0030 の「5% を超えたら学習に進まない」を満たした。
- 有効か: 速さは 1 回ずつの計測で、v17 の計測はもう一方の GPU の smoke test と時間が重なった (下の「速さ」)。行動はランダムで、学習済みの方策の手ではない。学習の効果は何も示さない。

## 目的と仮説

[0030](../decisions/0030-v17-shorter-wait-phases.md) の「実装の見通し 3」。v17 は v15 の設定クラスの `durations` だけを差し替えた版なので、確かめるのは次の 4 つ。

1. 尺が `decimation`・手数の上限・行動の項の尺まで写っている (Hydra で尺を変えたときの「追随しない」事故が無い)。
2. Play の手数の上限が 18 になる (v4 の Play の式のままだと 591 で 19 になることを実装のときに計算で見つけ、v17 の `play_post_init` で 17.5 手ぶんにした)。
3. 発散が増えない (5% を超えたら学習に進まない)。
4. 速さが 0030 の予想 2 (v15 の 0.78 倍、0.75〜0.81) の範囲。

### 速さと発散 (bench、4096 環境、ランダムな行動、計時 3 手 + 内訳 3 手)

| | 1 手の時間 (素) | 1 手の時間 (同期あり) | PhysX の 1 ステップ | 1 手あたりの発散 (24576 手) |
|---|---|---|---|---|
| v15 | 57.29 s | 58.90 s | 70.2 ms | 3.36% |
| v17 | 43.87 s | 45.33 s | 69.5 ms | 3.76% |
| v17 / v15 | **0.766** | 0.770 | 0.99 | +0.40 ポイント |

- 物理ステップ数の比は 591 / 759 = 0.779。PhysX の 1 ステップの重さは同じなので、速さはほぼステップ数の比になった。
- 発散は 0030 の D4 の計測 (`outputs/bench_step_time/n4096_D4`、v14 の設定に尺を上書き) と同じ 3.76% だった。物理が同じで、同じ seed・同じ行動の流れなので、値が一致したと見られる (推測)。
- **v17 の計測は、GPU 0 のスモークテスト (23:25:28 に終了) と終わりの 1 分ほどを除いて重なった** (v17 の bench は 23:26:32 に終了)。v15 の計測の間は GPU 0 は空いていた。CPU の取り合いがあれば v17 が遅く出る向きなので、0.766 は控えめな値 (推測)。

## 結論

- 分かった: v17 の尺は学習・Play の両方で意図どおりに組み上がり、Play の手数の上限は 18 (v4 の式のままなら 19)。1 手の時間は v15 の 0.766 倍で、予想 2 の範囲 (0.75〜0.81) に入った。1 手あたりの発散は 3.76% で、5% の線を下回った。ゲート 1 は 0030 の D4 と同じ 64/128。
- 推測: 1 手の終わりにまだ動いているロープが v15 の約 3 倍あることが、学習の信号に効くかもしれない (0030 の予想 1・4 で見る)。
- 未確認: 学習済みの方策の手での発散と速さ (学習ログと chain 評価で見る)。速さの計測の揺れ (各 1 回)。
