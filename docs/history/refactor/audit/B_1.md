## 1. 方法と凡例

* 6 文書を全文読み、見出しごとに分類した。長い節は分類が変わる行で分けた。
* 文書の作成・更新の日時は `git log --follow` で確かめた (§7 B-1・B-11)。
* 文書が挙げるログ・出力のパスは `ls` で在否だけを確かめた (中身は開いていない)。

分類の略号:

| 略号 | 分類 | 置き場所の原則 |
|---|---|---|
| Spec | Current specification | コードの近く、または `docs/system/` |
| Rat | Design rationale | 局所的なら docstring、横断的なら `docs/decisions/` |
| Res | Verified result | `docs/experiments/` (条件・seed・iteration・評価の方法を併記) |
| Hyp | Hypothesis | 「仮説」と明記し、検証の計画と一緒に置く |
| Open | Open question | `docs/STATUS.md` の「次の作業」か課題の一覧 |
| Repro | Reproducibility metadata | 実験記録の中 |
| Hist | Historical context | `docs/history/` |
| Obs | Obsolete information | 削除の候補。再現に必要なら `docs/history/` へ |

「主な分類」の列は多い順。置き場所のファイル名 (例 `docs/experiments/rope_study.md`) は提案で、決まったものではない。
打ち切った 2 つの研究の Open は、`docs/STATUS.md` の「保留 (打ち切り中)」に置く前提で書いた (所見 B-16)。
