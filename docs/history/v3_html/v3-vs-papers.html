要旨

  1. 取り込んだ: 到達した形からエピソードを始める (TWISTED-RL §IV-D / TWISTED の到達木)、目標に達したら終了する (TWISTED-RL)、p-data グラフの BFS (TWISTED / TWISTED-RL の高レベル)。v2-R2 時点で Report が「中核が入っていない」と指摘した 5 つのうち 3 つに手を付けた。
  2. 置き換えた: 論文は結び目理論 (BFS) を推論時の計画に使い、方策に「次に行う移動」を渡す。v3 は BFS を学習時の報酬 (ポテンシャル)に畳み込み、方策は 1 つのまま、0 から固結びまでを通しで解く。エピソードも「1 遷移」ではなく「課題全体」のまま。
  3. まだ無い: 推論時の探索、遷移ごとのスキルと移動での条件付け (TWISTED-RL-C)、対称性によるデータ拡張、off-policy 学習。論文の成功率は探索込みの数字なので、v3 の 1 回展開の成功率とはそのまま比べられない。
  4. 設計上の注意点 解釈: (a) C1 のアーカイブは既定の 1024 環境だとほぼ 1 iteration で全部入れ替わり、「これまでに到達した多様な形」ではなく「直近の分布」になりやすい。(b) 段の初回ボーナスは観測に無い「最高段」に依存するので、段を落として登り直す場面で報酬が非マルコフになる。(c) 12 手のエピソードでは 1 手 5% の発散が約半分のエピソードを終わらせる。
  5. 報酬の居座りの局所解は解消した。概算では、C1 を作って維持するだけの割引収益と理想経路の比が v2-R2 の約 1 : 3 から、v3 では約 1 : 7 になる。

01出発点: Report の診断 (v2-R2 時点)

Report.md の結論は、v1〜v2-R2 が詰まっていたのは報酬の細部ではなく問題の定式化のせいだ、というものでした。v0 (交差 1 つ) は学習でき、v2 は偽の C2 に居座り、v2-R2 では本物の C2 が課題として残りました。これは TWISTED の SAC+HER ベースラインの「交差 1 は解けるが、交差 2 ではほぼ 0」と同じ構図です。論文はこの壁を報酬ではなく、次の仕組みで越えています。

v2-R2 が論文から引き継いでいたもの

位相表現 (p-data) と、pick&place 1 回を 1 行動にする粒度の 2 つだけ。

入っていなかった論文の中核

高レベルの位相計画 / 1 遷移 = 1 エピソード / 移動を条件にした方策 / 到達した状態からのリセット / 推論時にシミュレータを使う探索。

v3 はこのうち「到達した状態からのリセット」を P1-1、「目標で終了」を P1-2、「位相グラフ」を P1-3 として、PPO の単一方策のまま入れられる形で取り込んだ版です。

03結び目理論を「どこで」使うか

いちばん大きな違いは、位相グラフ (結び目理論の知識) が入る場所です。

v3 の形の利点

方策が 1 つで済み、推論時に計画器もシミュレータも要らない。PPO と Isaac Lab の manager の仕組みの中にそのまま収まる (新しいのは event 項 1 つと報酬項 2 つだけ)。移動の条件付けに必要な「p-data の区間番号から ρ(A) を作る」処理も要らない。

v3 の形の欠点

TWISTED-RL が示した「移動で条件付けたスキルは複雑な状態に移せる」(4-Eval で TWISTED の 10% → 26%) という性質を使えない。固結び以外の結び目を結ぶには、報酬の表を作り直して学習し直す必要がある。「次の遷移に失敗したら別の遷移を試す」という再計画もできない。

04エピソードの切り方

TWISTED-RL の多段エピソードの利点 (位相を保ったまま形を整える手が打てる) は、v3 でもそのまま得られています。位相の変わらない手の整形報酬は −0.017〜−0.033 と小さく、TWISTED-RL の「維持 0」に近い扱いです。

一方、手数の目安は論文と合っています。TWISTED-RL の 3-Easy の成功例は 1 遷移あたり平均 2.5 手で、固結びは 3 遷移なので約 7.5 手です。ゲート 1 の台本は 5 手でした。v3 の 12 手はこれに把持の失敗のやり直しを足した長さです。

05考察 1: 到達状態アーカイブ

狙いは論文と同じで、「偶然 C1 に着いたエピソードの残りの手」でしか C2 を練習できなかった v2-R2 の問題 (Report §5.3、論文との差で最も効いていると見た点) を直接埋めます。ただし保存と選び方の細部が論文と違い、そこから起こりそうなことがあります。

C1 の箱はほぼ毎 iteration 入れ替わる 解釈

smoke test (64 環境 × 12 手 = 1 iteration あたり 768 手) では、C1 の件数が 141 → 417 → 672 と 1 iteration に約 270 件ずつ増えました。手の約 35% が C1 で終わっている計算です。同じ割合で既定の 1024 環境 (1 iteration 12,288 手) に当てはめると、1 iteration で約 4,300 件が入り、容量 4,096 を超えます。

つまり C1 のアーカイブは「これまでに到達した多様な C1」ではなく、「直近 1 iteration に方策が作った C1」になりやすい。Go-Explore や TWISTED-RL が狙う「過去に到達した形を一様に使う」性質とは違い、方策が偏ると初期状態も同じように偏ります。C2 も数十 iteration で同じ状態になります。smoke test の割合はほぼランダムな方策のもので、学習が進めば変わる点には注意が要ります。

同じ形が何度も入る 解釈

アーカイブは「その手で段が上がったか」を問わず、手の終わりの形を毎手入れます。アーカイブの C2 から始めて C2 のまま動けなかったエピソードは、ほぼ同じ形を最大 11 回入れ直します。smoke test で C2 が 1 iteration に 7〜12 件増えていた (1 手あたり約 1.2%、ランダムな方策の本物の C2 の約 0.3% の 4 倍) のは、この再登録を含んでいる可能性があります。これが多いと、アーカイブは「方策が先へ進めない形」で埋まっていきます。

段の単位は粗い

「cover の後」(次の 1 手で結べる) と、普通の輪は同じ C1 の箱に入り、比率は出現頻度で決まります。TWISTED-RL は位相状態ごとに一様に選ぶので、まれな状態も同じ確率で練習できます。v3 には BFS のキー (batch_keys) が既にあるので、同じ粒度にするのは難しくありません。

改善案 (§11 の 2):

  • 段が上がった手の形だけを入れる (TWISTED-RL の「l → k へ遷移した形」と同じ)。再登録と C1 の氾濫が同時に減る。
  • p-data のキーごとに箱を分け、キーを一様に選ぶ (TWISTED-RL の S ごとの一様選択)。または BFS の d で重みを付けて、d = 1 の状態 (cover の後・本物の C2) を多めに選ぶ。
  • 容量を増やすか、上書きをリザーバサンプリングにして、古い形も確率的に残す。

評価の見方は論文と同じ方向

アーカイブから始めたエピソードは途中から始まるので、成功率が水増しされます。smoke test でも固結びはアーカイブ始まりのエピソードでだけ出ました (archive_success 0.075、scratch_success 0)。これは TWISTED-RL の C 版で後の段の方策が「途中の形」から学ぶのと同じ構図で、最初に伸びるのは最後の段 (C2 → 固結び) のはずです。archive_success が上がっても scratch_success が 0 のままなら、前半の段 (0 → C1 → C2) が詰まっている、と読めます。

06考察 2: 報酬と終了

居座りの局所解は解消した

Report §5.5 は、v2-R2 の「毎手払う状態ボーナス」では C1 を作って維持するのが強い局所解だと指摘しました。v3 の報酬を同じ考え方で概算すると、次のようになります。

行動の方針v2-R2 (6 手)v3 (12 手)
1 手目で C1 を作り、あとは維持するだけ約 2.9約 0.68
2 手ずつで C1 → C2 → 固結び (理想)約 8.9約 4.8
比 (理想 / 居座り)約 3.1約 7.1

v2-R2 の値は Report §5.5 から。v3 の値はこの文書での概算で、γ = 0.95、Φ は段 / 3 (ラダーと BFS がこの経路で一致する)、罰則は 0 と仮定しました。居座り = 0.5 + 0.95 × 1/3 に、残り 11 手の −0.017 を割り引いて足したもの。理想 = 2 手目に C1 (+0.817)、4 手目に C2 (+1.8)、6 手目に固結び (+3.283) をそれぞれ割り引いて足し、維持の手の小さな負を引いたもの。

整形報酬はポテンシャルの差なので、状態を行き来しても稼げません。初回ボーナスも各段 1 回しか払わないので、どちらも「繰り返して稼ぐ」ことができない設計です。TWISTED-RL の「目標で +1 して終了」とは形が違いますが、居座りと判定の抜け道の繰り返し利用を防ぐという目的は果たしています。

段を飛ばすと合計を払う設計は、cover 経路を不利にしない

ゲート 1 では、成功の多くが本物の C2 を経由せず、「cover の後」(R2 除去後は C1) から tuck 1 手で固結びになっていました。初回ボーナスは R2 除去後の段で払うので、cover の手には +1.5 が付きません。しかし段を飛ばした手には飛ばした段のぶんも払う (C1 → 固結び で +4.5) ので、総額は C2 経由と同じです。差は +1.5 を 1 手早くもらえるかどうかの割引だけ (1.5 × 0.05 ≈ 0.075) で、経路の選り好みはほぼ生じません。cover の手そのものは BFS の整形 (+0.30) で評価されます。

初回ボーナスは観測に無い情報に依存する 解釈

初回ボーナスの額は「このエピソードの最高段 (best)」で決まりますが、best は観測に入っていません。観測には現在の段しかありません。そのため、段を落としてから登り直す場面で、同じ観測・同じ行動でも報酬が違います (初めてなら +0.5 / +1.5、2 度目なら 0)。critic は MLP なので区別できず、価値の目標がぶれます。影響するのは段を落とした後だけなので大きくはないはずですが、手数を 12 に延ばしたぶん起きやすくなっています。best の one-hot (4 次元) を観測に足すか、GRU / LSTM 版と比べると確かめられます。

意図しない遷移には −1 が無い

TWISTED-RL は目標でない位相に変わったら −1 で終了します。v3 では、段を落とす手は整形で −Φ の差 (C1 → 自明で −0.333) を受け、エピソードは続きます。偽の C2 のように Φ が変わらない横の移動は、ほぼ 0 です。TWISTED-RL の著者は脚注で「すべての失敗に同じ罰を与えると、罰が溜まらないよう早く終わらせる方策が好まれる」と注意しています。v3 で同じことが起きるかを確かめると、C1 の状態から発散で終わらせると −0.1 − 1/3 ≈ −0.43 で、残り 11 手を居座る場合の約 −0.14 より悪いので、「わざと発散して逃げる」動機はありません。

成功時の Φ = 1 は、固結びのボーナスを 0.95 足すのと同じ

Ng らの保証 (整形が最適方策を変えない) は、エピソードの終端でポテンシャルを 0 と置いたときに成り立ちます。v3 は発散の終端では 0 にしますが、固結びの終端では Φ = 1 のまま払います。これは保証の外側で、実質的には固結びのボーナスが 3.0 から約 3.95 に増えるのと同じです。目的 (固結びを作る) と同じ向きの変更なので害は無いはずですが、「整形は最適方策を変えない」とは厳密には言えなくなっている点は覚えておく価値があります 解釈。

07考察 3: BFS ポテンシャルと高レベル計画

「距離」に畳むと失うもの・得るもの

失うもの

どの移動をするか。計画は「次は区間 2 を区間 0 の上へ Cross」まで決めるが、距離の表は「ゴールまであと 1」しか言わない。d = 1 の状態へ向かう手を方策がロープの形から探す必要がある。

経路の選択。固結びへの経路は複数あり (Yan2020 は鏡像を含めて 8 通りとしている)、計画は失敗したら別の経路に切り替えられる。距離の表は最短のものに寄せるだけ。

得るもの

条件付けが要らない。方策の入力は固定長のまま。ρ(A) の符号化や、p-data の区間番号とロープのリンクの対応付けを実装しなくてよい。

論文より寛容なゴール。尻尾の余分な輪を許す 172 状態をゴールにしており、実物のロープで起きる「結び目 + 余分な交差」を取りこぼさない。

p-data に見えない差は critic が担う 解釈

輪 1 つの 4 通りはどれも d = 2 で、Report §5.4 が問題にした「次の手が打てる輪 / 打てない輪」の差は p-data には現れません (幾何の差)。Yan2020 は、多段の微調整で「次のプリミティブの価値 V(s′) を前のプリミティブの報酬にする」ことでこの差を学ばせました。v3 では 1 つの critic が全段の価値を学ぶので、同じ役割を暗黙に担うことになります。ロープの形 (リンク位置) を観測に入れているのは、この意味でも必要です。

d は移動の回数で、手の数ではない

BFS の 1 歩は Reidemeister 移動 1 回ですが、pick&place の 1 手は移動 0 回 (整える手) のことも 2 回のこともあります。TWISTED-RL の成功例では移動 1 回に平均 2.5 手かかりました。Φ の刻み 1/3 は「移動 1 回ぶん」で、その間の整える手には整形の信号がほとんど無い、という点は TWISTED-RL の「維持 0」と同じ性質です。

他の結び目への拡張

交差 4 で打ち切っているので、固結び (交差 3) には足りますが、8 の字結び (交差 4) の途中状態には交差 5 以上が現れうるので、表を広げる必要があります。交差 4 までで 7,968 状態、列挙に約 20 秒なので、交差 5 は桁が 1 つ以上増えると見込まれます 解釈。

「掴んだ側が上になる」は Yan2020 が構造に組み込んだ性質そのもの

pick&place では掴んだ部分が必ず上に置かれるので、固結びの「下」を作るには輪の側を掴んで尻尾の上に被せる (cover) しかありません。これは Yan2020 がネットワークの構造に組み込んだ規則性「新しい交差で上になる区間を掴み、下になる区間へ運ぶ」と同じで、Yan2020 の固結びの経路 C(2, 0, 1) も「区間 2 (輪) を区間 0 の上へ」です。v3 の方策はリンク位置を平らに並べた MLP なので、この規則性を一から学ぶ必要があります。Yan2020 のように「上になる区間 / 下になる区間 / 全体」に分けた入力や attention を使えば、学習が速くなる余地があります 解釈。

長いエピソードは発散に弱い 解釈

論文は MuJoCo の自由なエンドエフェクタで、発散の話は出てきません。v3 は指の摩擦だけで掴むので、接触が原因の発散が起きます。smoke test では 1 手あたり約 5% でした。12 手を打ち切るまで発散しない確率は 0.9512 ≈ 0.54 で、「エピソードの約半分が発散で終わる」という観測と合います。TWISTED-RL のように遷移ごとの短いエピソードなら、1 エピソードあたりの影響は小さくなります。1 手の発散率を 2% に下げれば、12 手で発散する割合は約 22% まで下がります。

v3 の方が現実に近い点

把持は指の摩擦で、掴み損ね (把持距離の罰で測る) やロープの滑りが起こる。成功の判定は、ハンドを退避させてロープが床に落ちた後に測る。

論文と同じ単純化

腕が無く、ハンドを直接動かす (IK・可達範囲・自己衝突が無い)。ロープの状態は完全に観測できる。TWISTED-RL が限界に挙げた sim2real の課題は v3 にもそのまま残る。

11次に試すこと (優先順)

  1. 本番の学習と、3 つの切り分け

    v3 は P1-1〜P1-3 を同時に入れました。Report §8 は「アーカイブと報酬を別々に入れて比べる」ことを勧めていたので、Hydra の上書き (prob=0.0 / knot_tied=null / potential=class) で 1 つずつ外した run を並べます。見る指標は scratch_success、archive_success、restore_mismatch、段ごとの発散率。

  2. アーカイブの保存と選び方を論文に寄せる

    段が上がった手の形だけを保存し、p-data のキーごとに一様に (または BFS の d で重みを付けて) 選ぶ。まず arc_size_c1 が毎 iteration 上限に張り付くか、キーの種類がいくつあるかをログで確かめる (§05)。

  3. 最高段 best を観測に足す

    4 次元の追加で初回ボーナスの非マルコフ性が消える。観測の次元が変わるので、v3 の中で比べるなら新しいバージョンにする (§06)。

  4. 発散率を下げる

    12 手ではエピソードの約半分が発散で終わる。学習が進んでも下がらないなら、尺をさらに延ばすか手数を戻す。ゲート 1 で未解明のまま残った「env.step で再生すると台本より発散が多い」理由の調査もここに含まれる。

  5. 推論時の探索を評価に加える

    アーカイブの復元の部品を使い、状態を N 環境に複製して候補を試す。論文と同じ土俵の成功率が出せる (§10)。

  6. 段別のタスク (TWISTED-RL-C 相当)

    1〜5 で前半の段 (0 → C1 → C2) が詰まったままなら、アーカイブから段 k だけを始める専用タスクに分け、段が変わったら終了・+1 / −1 にする。対称性の拡張と SAC はその後。
