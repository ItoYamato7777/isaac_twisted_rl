## 0. 要旨

1. **v2-R2 が 3 論文から引き継いでいるのは「位相表現 (p-data)」と「pick&place 1 手 = 1 行動」の 2 点だけ**。3 論文に共通する中核 — 高レベルの位相計画、1 位相遷移 = 1 エピソードという分解、遷移 (Reidemeister 移動) を条件にした方策、到達済み状態からのリセット、推論時にシミュレータを使う探索 — はどれも入っていない。v2-R2 は「素の紐から固結びまでを 1 本の PPO 方策に 6 手で解かせる」フラットな定式化になっている。
2. **v1 → v2 → v2-R2 の経緯は、TWISTED 論文の SAC+HER ベースラインの結果をそのまま再現している**。同論文は「モデルフリー RL は学習中に 1 交差の問題はすべて解けたが、2 交差では成功率がほぼ 0」と報告している。v0 (1 交差) は成功し、v2 は偽の C2 に居座り、v2-R2 では本物の C2 が課題として残った。詰まっている原因は報酬の細部より、問題の定式化にある可能性が高い。
3. **v2-R2 の R2 除去そのものは正しい修正**。追加検証で、交差 8 個以下では除去の順序によらず結果が一致すること (約 3.2 万本のランダムロープで差 0 件) と、固結びの交差が消えないことを確認した。一方、ランダム方策でも**本物の C2 は 1 手あたり約 0.3% 起きている**。README の「smoke test の `r2_c2` は 0」は、16 環境 × 2 iteration という標本の小ささによるもの。
4. **実装上の不具合を 3 件見つけた**:
   - **(重大)** 把持距離が有界化されていない。ロープが発散すると非常に大きい有限値が罰則に入る。**現在走っている v2-R2 の run は iteration 1 で `Loss/value_function = 7.2e9`、`Episode_Reward/grasp_shaping = −107.8` を記録し、適応学習率が下限の 1e-5 まで落ちている**。
   - **(中)** 固結び・C2 の判定は先頭 8 スロットしか探索しない。そのため交差が 9 個以上あると、結び目が紐のどちら側にあるかで検出結果が変わる。
   - **(小)** C1 の定義が項によって違う (`success_c1` は交差数 ≥ 1、ラダーの class 1 は交差数 == 1)。
5. **効果が最も大きそうな改善** (詳細は §7):
   - (a) 到達した C1/C2 のロープ状態を保存しておき、そこからエピソードを始める (TWISTED-RL §IV-D の Go-Explore 型リセット)
   - (b) 成功したらエピソードを終える、または疎報酬を「段が上がった瞬間に 1 回だけ」払う形にする
   - (c) ポテンシャルを 4 クラスから「p-data の BFS 距離」に細分化する
   - (d) 推論時に学習済み方策を候補生成器として使う探索
   - (e) 未実施のゲート 1「台本で固結びが結べるか」を先に通す

## 2. 3 論文の要点 (実装との比較に必要な部分)

### 2.1 Yan2020 — Learning Topological Motion Primitives

- **3 層構成**: 位相グラフの探索 → 位相動作プリミティブ (学習) → 実機での MPC 追従 (MPPI + 視覚トラッキング)。
- **行動**: 制御点 3 つのスプライン (1 点目 = ロープ上の把持点、2 点目 = 最高点、3 点目 = 台上の置き先) による 6 次元の行動。「**多くの場合、1 位相動作は 1 スプラインで足りる**」としている。
- **プリミティブの分け方**: R1 / R2 / 端が上に来る Cross / その他の Cross の 4 つ。各位相動作は over index・under index・left・sign・over first という離散パラメータで符号化し、ネットワークに入力する。
- **ネットワーク構造**: ロープ形状を「新しい交差で上に来る区間」「下に来る区間」「全体」の 3 系列に分けて入力し、系列間を attention でつなぐ。人間が「上に来る区間を掴み、下に来る区間へ運ぶ」という動作の規則性を構造に組み込んでいる。
- **学習**:
  - 人間のデモ (画像上で 3 点をクリックし、ノイズを加えて 320〜480 回試行) で QT-Opt (critic + CEM) と actor (REINFORCE) を初期化する。
  - その後、**より広い初期形状で RL を追加すると成功率が 1.14〜2.33 倍に上がった**。
  - 最後に、多段で同時に微調整する。このとき、**次のプリミティブの価値 V(s′) を前のプリミティブの報酬として使う**。「次の手が打ちやすい幾何」を学習で獲得するための仕組み。
- **対称性**: Mirror / Reverse 変換で、学習すべき位相動作の種類を減らしている。
- **推論**: 学習したプリミティブを候補生成器として木探索する。固結び (R1(0,1,1) → C(0,1,1) → C(2,0,1)) は、木のノード数 3 (理論下限) 〜 5 以内で見つかった。

### 2.2 TWISTED — 位相探索 + 逆モデル (デモ無し)

- **環境**: MuJoCo。自由に動くエンドエフェクタ。行動は曲線 `c = (掴むリンク l, 最高点 z_max, 置き先 x, y)` で、軌道は grab-lift-move-lower。**位置の正解は絶対座標で、z_max も行動に含まれる**。
- **高レベル**: R1 / R2 / Cross を辺とする p-data グラフを BFS し、目標より交差数の多い状態は枝刈りする。
- **低レベル**: 自己回帰の逆モデル (リンク → z_max → x → y) で候補曲線を K=6 本生成し、**シミュレータで実際に試して**、目標の位相に達したものを採用する。
- **探索**: 到達したロープ状態の木 T を持つ。そこから「交差数に比例して優先する」規則で開始状態を選ぶ。確率 p=0.05 でランダムに展開して網羅性を保つ。
- **データ**: 到達済み状態から乱数の曲線を打ち、交差が増えた遷移だけを残す。537 遷移/時/コア、計 167 万点 (廃棄率 99% 超、3 週間)。Mirror / Reverse で拡張する。
- **示唆的な実験**:
  - **SAC+HER のベースラインは 1 交差の問題はすべて解けたが、2 交差ではほぼ 0**。論文は、位相状態が離散で状態間の類似性が無いことを原因と考察している。
  - 曲線を離散化しただけで、到達する位相の一致率が 82% に落ちる (行動に高い精度が要る)。
  - 摩擦 ±5% には頑健。

### 2.3 TWISTED-RL — 逆モデルを「遷移ごとの多段 RL スキル」に置き換え

- 高レベルは TWISTED と同じ。低レベルを、**高レベルの行動 (R1/R2/Cross とそのパラメータを符号化した ρ(g)) を条件とする SAC 方策**に置き換えた。入力はリンク位置のみ (姿勢は捨てる) + ρ(g)。
- **1 エピソード = 1 位相遷移**:
  - 最大 M 手 (移植元コードでは 7 手)。**位相が変わった時点で終了**する。
  - 報酬は **目標に到達 +1 / 現状維持 0 / それ以外の遷移 −1** の疎報酬のみ。
  - 同じ位相の中で「整える手」を打てるのが TWISTED との主な違い。
- **エージェントの分け方**: G (1 個) / A (移動の種類別) / C (交差数別) / AC (両方) を比較し、**C が一貫して最良**だった。
- **目標と初期状態の選び方** (§IV-D, 付録 VIII-B.2) — 本レポートで最も重要視する点:
  - 目標とする遷移は一様に選ぶ。
  - 初期状態は、**その位相状態について学習中に到達したロープ形状から一様に選ぶ** (Go-Explore に着想)。
  - 交差数 k の方策に必要な初期形状は、それより前の段の学習中に「l→k (k>l) の遷移で到達した形状」を貯めておいて使う。
- **規模**: 方策 1 つあたり 2M env step、4 日以内。
- **結果** (30 分の探索上限、5 seed):
  - 3-Easy はどの手法も 100%。TWISTED-RL-C は約 3 倍速い。
  - 3-Medium 44% (1 時間なら 62%)、3-Hard 46%、3-Eval 61%、4-Eval 26%。TWISTED は 4-Eval の 10% 以外すべて 0%。
  - 3-Easy の成功例では、**1 遷移あたり平均 2.5 手**を使っている。
- 著者自身の限界の記述: 同じ罰則をすべての失敗に与えると「早くエピソードを終わらせたい」局所解が生じうる (脚注 2)。自由に動くエンドエフェクタと完全な状態観測を仮定している。

## 5. 比較からわかること

### 5.1 v1〜v2-R2 の詰まりは、TWISTED の SAC+HER ベースラインと同じ現象

TWISTED §5.2 の記述は次のとおり:

> during training … it did manage to consistently solve all 1-cross problems, but already for 2-cross problems success rate was near zero.

v0 (1 交差) は成功した。v1 は疎報酬が発火せず発散した。v2 は偽の C2 (輪を上から跨いだだけ) に居座った。どれもこの記述と同じ構図になっている。論文はこの壁を**報酬ではなく定式化の変更**で越えている (高レベル計画、1 遷移ごとのエピソード、到達状態からのリセット)。v2-R2 は偽の C2 という抜け道を塞いだ段階で、「本物の C2 を探索で見つける」問題はそのまま残っている。

ただし v2-R2 の初期ログを見ると、見込みは README の記述ほど悲観的ではない:

| 指標 (1 手あたり、全環境平均) | iter 0 | iter 1 |
|---|---|---|
| `r2_c2` (本物の C2) | 0.34% | 0.28% |
| `fake_c2` (偽の C2) | 1.25% | 1.33% |
| `r2_c3` (固結び) | 0.004% | 0.004% |

1 iteration は 12,288 手なので、**本物の C2 は 1 iteration に約 35 回観測されている**。README の「smoke test の `r2_c2` は 0」は 16 環境 × 2 iteration という標本の少なさによる。PPO がこの信号を拾えるかは、§6.1 のバグを直してから確かめる価値がある。

### 5.2 論文の「成功率」と v2-R2 の「成功」は別物

TWISTED / TWISTED-RL / Yan2020 の成功率は、どれも**シミュレータを完全な世界モデルとして使い、最大 30〜60 分探索した結果**である。候補の手を実際にシミュレートし、うまくいったものだけを採用し、失敗したら到達木の別の状態からやり直す。TWISTED-RL の方策の成功率が低くても、探索がそれを補っている。

v2-R2 が目指しているのは「方策を 1 回展開して 6 手で結ぶ」ことで、論文より難しい目標になっている。論文と比べるなら、学習済み方策に同じ枠組みの探索を組み合わせるべき (§7 P2-3)。Isaac Lab の並列環境は、この「候補を N 本同時に試す」処理に向いている。

### 5.3 「干し草の中の針」を、論文は初期状態の選び方で解いている

TWISTED の記述では、ランダムな手では 3 交差の状態に**1 コア 1 時間で 27 個しか**到達できず、到達済みの状態から再開する方式にして初めて 537 個に増えた。TWISTED-RL も交差数 k の方策の初期状態を「前の段で到達した形状」から取る。

v2-R2 は毎回まっすぐなロープから 6 手で始めるので、C2 の練習ができるのは「偶然 C1 に着いたエピソードの残りの手」だけになる。**論文との差で最も効いているのはここ**だと考える。README の末尾にある「C1 からの初期化」は、論文が実際に採用し効果を示している方法である。

### 5.4 ラダーが粗く、「次の手が打てる C1」と「打てない C1」を区別できない

pick&place では**掴んだ区間が必ず上に置かれる**。`test_r2_reduce.py` の幾何で確かめると:

- 先端側を運んで輪を作る (R1) と、交差 A で先端側が上 (O) になる。
- 続けて先端を輪へ差し込む (Cross) と、先端はまた上 (O) になる。
- 結果は **OO になり、R2 で交差 0 に戻る**。本物の C2 (OU) にするには、**輪の側を掴んで先端の上に被せる**必要がある。

Yan2020 の固結びの手順 C(2,0,1) も「区間 2 (輪) を区間 0 (先端) の上へ」であり、同じことを言っている。

v2-R2 のラダーはこのどちらの C1 にも同じ Φ=0.35 と `success_c1` +0.5 を払う。TWISTED / TWISTED-RL の高レベル計画は R1 の**種類** (sign・left・over first) まで区別した p-data で経路を決める。Yan2020 は、次のプリミティブの価値を前のプリミティブの報酬に使って「次の手が打てる幾何」を学ばせている。**段の粒度を p-data 単位に細かくすること**が改善の方向になる (§7 P1-3)。

### 5.5 報酬: 毎手払う状態ボーナスは、偽の状態を悪用されやすい

v2 / v2-R2 の `success_c1/c2/success` は、条件を満たしている間**毎手**払われる。累積すると C1 に居るだけで 1 手 0.5、C2 で 2.0、C3 で 5.0 になる。γ=0.95、6 手で概算すると:

| 行動方針 | 割引収益 (概算) |
|---|---|
| 1 手目で C1 を作り、あとは維持するだけ | 約 2.9 |
| 2 手ずつで C1 → C2 → C3 (理想) | 約 8.9 |

本物の C2 の成功率が 1 手 0.3% 程度では、C1 を壊す危険を冒して C2 を狙っても期待値が見合わず、**C1 に居座るのが強い局所解**になる。v2 で偽の C2 に居座られたのも同じ仕組みで、判定の抜け道は毎手払われる報酬として繰り返し悪用される。

TWISTED-RL は「目標に到達したら +1 で**終了**」とし、そもそも居座りようがない。「ポテンシャル整形は最適方策を変えない」という保証 (Ng et al.) 自体は正しいが、この保証は状態ボーナスで決まる目的関数に対するものであり、「固結びを作る」だけを目的にした問題とは一致しない点に注意が要る。

### 5.6 行動空間の違い

- **z_max (運搬高さ)**: TWISTED / TWISTED-RL では行動の一部。TWISTED の離散化の説明からは、振れ幅が 0.07 程度 (xy の作業域 1.0 に対して) と読み取れる。つまり**低く持ち上げる動作を精密に選べる**。v2-R2 は 0.20 m (全長 0.82 m の約 1/4) で固定なので、毎回ロープの大部分を持ち上げて引きずる。交差を狙った位置に作りにくく、発散の原因にもなりうる。
- **置き先の指定**: 論文は作業域の絶対座標。v2-R2 は「掴んだリンク ±8 の target リンク + ±0.123 m」の相対指定。相対指定には移動に依存しないという利点がある。一方、**`drop_xy_max` = 0.123 m は最小ループ周長 0.251 m の半分**という指摘が [next_action.md §4.8.9](../src/isaac_twisted_rl/tasks/knot_tying/next_action.md) にあり、まだ検証されていない。
- **yaw**: 論文には無い自由度。探索空間を広げるだけになっている可能性がある (§6.5)。

### 5.7 判定は論文より寛容で、その分抜け道の検証が要る

論文の成功判定は目標の p-data と完全に一致すること。v2-R2 は、尻尾に余分なループがあっても固結びを取りこぼさないよう部分列判定を使い、偽陽性を R2 除去で抑えている。これは実物のロープに合わせた妥当な工夫である。

ただし R2 だけを除去対象に選ぶ理由は理論的に一意ではない。例えば両端が自由な紐では、「端から見て全部上 (または全部下) の区間は引き抜ける」という簡約も成り立つ。README の偽の C2 `1U4+_2U5-_3U6+_4O1+_5O2-_6O3+` は、尻尾側が 3 交差とも O なので、引き抜けば交差 0 になる。「どの簡約を認めるか」は「どの状態を段として数えるか」という設計判断であり、今後も `fake_*` の監視を続ける必要がある。p-data グラフ上の距離でポテンシャルを定義すれば (§7 P1-3)、この任意性は小さくなる。

### 5.8 物理的に結べるかどうかが未検証

論文は、結び目が結べることが確かめられた MuJoCo のロープを使っている。v2-R2 の `twist` は「20 リンク × 4 cm、関節 ±60°」で、1 周のループだけで 6 リンク以上を使う。コード中でも `fine` プリセットに「**結び目が結べる**分解能」と注記されている ([rope_task_cfg.py の `_PRESET_DOCS`](../src/isaac_twisted_rl/tasks/knot_tying/common/rope_task_cfg.py))。

[v2 README §6](../src/isaac_twisted_rl/tasks/knot_tying/versions/v2/README.md) のとおり、**台本で固結びが結べるか (ゲート 1) は一度も実行されていない**。これが通らなければ、報酬をどう設計しても学習できない。学習よりこちらを先に確かめるべき。

### 5.9 スループットは論文より有利で、使い道はある

TWISTED-RL は 2M step に最大 4 日かかっている (約 6 step/秒)。v2-R2 は約 53 手/秒で、1 桁速い。この差は、到達状態のアーカイブからのリセットや推論時探索のように「状態を大量に試す」手法でこそ活きる。

## 6. 実装の問題点

### 6.1 【重大】把持距離が有界化されておらず、ロープの発散で学習が壊れる

- **場所**: [actions.py:532-541](../src/isaac_twisted_rl/tasks/knot_tying/common/mdp/actions.py#L532) `_record_grasp_distance` → [rewards.py:231](../src/isaac_twisted_rl/tasks/knot_tying/common/mdp/rewards.py#L231) `grasp_distance_penalty`
- **原因**: `torch.nan_to_num` は NaN/Inf しか置き換えない。ロープが「有限だが数 km」の座標に飛んだ場合、その距離がそのまま罰則 (−0.05·d) になる。また終了判定 [`rope_diverged`](../src/isaac_twisted_rl/tasks/knot_tying/common/mdp/terminations.py#L28) は z > 5 m しか見ておらず、判定されたステップの報酬もそのまま計上される。
- **証拠** (v2-R2 run `2026-09-26_15-57-53`):

  | iter | `Episode_Reward/grasp_shaping` | `Loss/value_function` | `Loss/learning_rate` |
  |---|---|---|---|
  | 0 | −0.000147 | 0.47 | 5.1e-4 |
  | 1 | **−107.8** | **7.2e+09** | **1.0e-5 (下限)** |

  critic の目標値が 10 桁跳ね、適応スケジュールが学習率を下限まで下げている。**このまま回しても v2 との比較にならない可能性が高い**。
- **修正案**:
  1. `dist` を物理的に意味のある上限 (例: ロープ直径の 5 倍) で `clamp` する。
  2. 発散した環境 (`~isfinite` または座標が作業域外) は、`failure` 以外の報酬を 0 にする。
  3. `rope_diverged` に「xy が env 原点から数 m 以上離れた」「リンク速度が閾値を超えた」の条件を加える。
  4. 念のため `rope_link_positions` の観測も `clamp` する。

  直したうえで v2-R2 を再度最初から学習させる。

### 6.2 【中】発散率が 1 手あたり約 3.8% と高い

v2-R2 の `div_cls0` (2.4%) + `div_cls1` (1.4%) を足すと、1 手あたり約 3.8% になる。6 手のエピソードなら約 2 割が物理の発散で終わる計算で、`Episode_Termination/diverged` の 0.16〜0.20 とも合う。[env_cfg_base.py](../src/isaac_twisted_rl/tasks/knot_tying/common/env_cfg_base.py) に記録されたランダム方策の実測値 1.2% の約 3 倍で、報酬のノイズ源になっている。§5.6 の「0.20 m 固定の運搬高さで大部分を持ち上げる」ことが一因かもしれない。z_max を行動に入れるか下げたうえで、発散率を測り直すことを勧める。

### 6.3 【中】固結び・C2 の判定が先頭 8 スロットしか見ず、結び目の位置で結果が変わる

- **場所**: [knot_detect.py:150](../src/isaac_twisted_rl/tasks/knot_tying/common/topology/knot_detect.py#L150) `num_slots = min(order.shape[1], MAX_CROSSINGS_CONSIDERED)`
- **原因**: スロットは `(seg_i, seg_j)` の辞書順、つまり**頭側のセグメントから順**に並んでいる。交差が 9 個以上になると、尻尾側の交差が探索から外れる。
- **再現** (付録 A-2): 三葉結びに独立した R1 ループを足した場合:

  | R1 ループ | 位置 | 交差数 | `is_overhand` | R2 後の class |
  |---|---|---|---|---|
  | 5 個 | 頭側 | 8 | True | 3 |
  | **6 個** | **頭側** | **9** | **False** | **2** |
  | 7 個 | 頭側 | 10 | False | 0 |
  | 6〜7 個 | 尻尾側 | 9〜10 | True | 3 |

- **影響**: 現状の交差数は平均 0.4 程度なので、実害は当面小さい。ただし学習が進んで交差が増えると効いてくる。docstring の「実用上の取りこぼしは無い」はスロットの**選び方**までは保証していない。
- **修正案 (情報を失わない)**: gap = 1 の交差 (R1 のねじれ) は、どの部分列でも gap 1 のままなので、gap k ≥ 2 の条件を**決して満たさない**。打ち切りの前にこれらを除けば結果は変わらず、上の例は解消する。そのうえで打ち切りに達した回数をログに出すとよい。

### 6.4 【小】C1 の定義が項によって違う

- [`crossing_achieved`](../src/isaac_twisted_rl/tasks/knot_tying/common/mdp/rewards.py#L80) (`success_c1`) は `count >= 1`。
- [`topology_class`](../src/isaac_twisted_rl/tasks/knot_tying/common/topology/knot_detect.py#L202) の class 1 は `count == 1`。

「輪 1 つ + R2 で消えない余分な交差 1 つ」の状態では、`success_c1` の +0.5 は払われるのに、ラダー上は class 0 (Φ=0) になり、`offladder` 罰まで受ける。どちらかに統一すべき。C2/C3 と同じく部分列の考え方を使うなら、「gap ≥ 1 の交差が 1 つ以上ある」でよい。

### 6.5 【小】行動のクリップで端の値に確率が集中する

`init_noise_std=1.0` のガウス方策に対し、環境は [−1, 1] でクリップする ([actions.py:255-275](../src/isaac_twisted_rl/tasks/knot_tying/common/mdp/actions.py#L255))。1 チャネルあたり約 32% の標本が端に張り付く:

- **yaw**: ±π は同じ角度なので、**約 32% が yaw = π に集中**する。
- **掴むリンク / Δlink**: 両端の値にそれぞれ約 16%。一様なら 1 値あたり約 6%。

PPO の対数尤度はクリップ前の値で計算されるので、勾配も偏る。tanh で押し込むか Beta 分布にする、あるいは `init_noise_std` を 0.5 程度に下げることを勧める。yaw は、ロープの接線に合わせる既定の把持姿勢があるので、行動から外すか ±π/2 程度に狭めることを検討してよい。

### 6.6 【情報】ログの整合性

- `logs/rsl_rl/knot_tying_v2/2026-09-24_14-07-21` の TensorBoard には **iteration 0〜35 の 36 点しか無い**。一方で `model_50.pt`〜`model_700.pt` は 2026-09-26 15:19 の同時刻に置かれている。v2-R2 README の「`model_700.pt` を再生した実測」は、このディレクトリの TensorBoard とは別の run の結果と思われる。出所 (どの run の何 iteration か) を README に書いておくと再現性が上がる。
- v2 の 36 iteration の中でも、`success_c2` は 0.0066 → 0.021 と早い段階から伸びていた。偽の C2 はかなり早い時期から悪用されていたことになる。

### 6.7 確認して問題なかった点

- ポテンシャル整形の Φ(s) と Φ(s′) は同じ判定器で測られている (`class_r2_at_action_start`)。抽出器は `update()` ごとに新しいテンソルを作るので、参照を保持する方式で正しい。
- 観測を reset 後の形状で計算するための `invalidate_extractor` の順序は正しい。
- R2 除去は、交差 8 個以下では順序によらず結果が一致した (付録 A-1)。固結びは削られない (既存テスト)。
- `num_steps_per_env = 12` が 6 手の整数倍であることなど、PPO 側の整合性は取れている。

## 7. 改善提案 (優先度順)

### P0: 学習を回す前に必ず

1. **§6.1 の修正** (距離の上限、発散した環境の報酬の無効化、発散判定の強化) をしてから、v2-R2 を最初から学習し直す。
2. **ゲート 1: 台本で固結びを結ぶ**。
   - `topology_debug.py` に 3〜6 手の台本を書く。例: 輪を作る → **輪の側を掴んで先端の上に被せる** → 先端側を引き出す。
   - `twist` で結べるか確かめ、結べなければ `fine` でも試す。
   - 同時に、6 次元の行動空間でその台本を表現できるか (Δlink ±8、±0.123 m で届くか) も確かめる。
   - 台本で得られたロープ状態は、次の P1-1 の初期アーカイブとしてそのまま使える。

### P1: 論文の中核を最小のコストで取り込む

1. **到達状態アーカイブからのリセット** (TWISTED-RL §IV-D、TWISTED の到達木 T)
   - 手が終わるたびに、R2 除去後の class (できれば p-data のハッシュ) ごとに、ロープの関節状態と root 姿勢を GPU 上のリングバッファへ保存する。
   - reset イベントで、確率 p (例: 0.5) でアーカイブから一様に選んで `write_joint_state_to_sim` / `write_root_pose_to_sim` で復元する。
   - TWISTED の知見に従い、交差数の多いクラスを優先して選ぶとよい。
   - Isaac Lab の EventTerm として素直に書ける。**§5.3 の差を直接埋める、最も効果が大きい変更**と考える。
2. **成功で終了 / 疎報酬を遷移ベースにする**
   - `success_*` を「エピソード内の最高段を更新した手にだけ」払う形にする。
   - class 3 に達したら終了する (`topology_reached` 型の DoneTerm。既存の [`topology_reached`](../src/isaac_twisted_rl/tasks/knot_tying/common/mdp/terminations.py) は交差数版なので class 版を追加する)。
   - これで §5.5 の居座りと、判定の抜け道が繰り返し悪用される問題が同時に消える。
   - 手数は 6 → 9〜12 に増やす (TWISTED-RL の実測は成功例で 1 遷移あたり平均 2.5 手)。成功で終了するなら、長いエピソードの弊害は小さい。
3. **ポテンシャルを p-data グラフ上の距離にする**
   - 移植元の BFS (R1/R2/Cross) で「固結びの p-data 4 通りまでの最短手数」を事前に表にする。
   - Φ(s) = 1 − dist(s)/dist_max とし、グラフに無い状態は 0 にする。
   - 実行時は、交差 3 個以下の `IntersectionBatch` を整数キーにハッシュして表を引く。p-data 文字列を作らなくてよいのでテンソル層で完結する。
   - §5.4 の「次の手が打てる C1 / 打てない C1」、§5.7 の簡約の任意性を同時に扱える。
   - さらに pick&place の「掴んだ側が上になる」制約を辺の条件に入れれば、実際に実行できる経路だけの距離になる。
4. **§6.3 と §6.4 の修正** (gap = 1 の交差を事前に除く、C1 の定義を統一する)。

### P2: 探索と汎化を強くする

1. **対称性のデータ拡張** (Yan2020 / TWISTED の Mirror / Reverse)
   - Isaac Lab の `RslRlPpoAlgorithmCfg.symmetry_cfg` (rsl_rl 3.0.1 の PPO に実装済み) で追加できる。
   - Reverse: リンク順を反転し、掴むリンクを N−1−l に、Δlink の符号を反転する。
   - Mirror: y を反転し、yaw・置き先 y の符号を反転し、交差の sign を反転する。class は変わらない。
2. **RND による好奇心探索**: `RslRlOnPolicyRunnerCfg.rnd_cfg` で有効化できる。疎な C2/C3 の探索に向いている。
3. **初期形状のランダム化**: 直線だけでなく、交差の無い曲線をランダムに初期状態にする。Yan2020 は広い初期形状での RL で 1.14〜2.33 倍の改善を報告している。v2 の方策が「全環境で同じ動き」になったのは、初期状態が決定的だったことも一因と考える。
4. **推論時の探索** (§5.2)
   - Play では、ロープの状態を N 環境に複製し、方策から N 本の手を標本して、段が上がったものだけを残す。これを繰り返す (TWISTED の K=6 候補、Yan2020 の木探索に相当)。
   - 評価には「1 回の展開での成功率」と「探索あり (時間上限付き) の成功率」の両方を載せると、論文と同じ土俵で比べられる。

### P3: 行動空間と定式化の見直し

1. **運搬高さ z_max を行動に入れる** (論文の主要なパラメータ)。0.20 m 固定を「数 cm〜0.20 m」の連続値にする。§6.2 の発散率も下がる可能性がある。
2. **行動の分布**: tanh / Beta にする、または初期 std を下げる。yaw の範囲を狭めるか、行動から外す (§6.5)。
3. **Δlink の範囲**: ゲート 1 の台本で ±8 が足りないと分かったら広げる。あるいは TWISTED のように「掴むリンク + 絶対座標の置き先」と比べる。
4. **遷移スキルへの分解** (TWISTED-RL-C 相当)
   - 交差数ごとにタスクを分け (`-v3-Stage1/2/3` の構想)、P1-1 のアーカイブから初期状態を取る。
   - 観測に「狙う遷移」のパラメータ (Yan2020 の over index / under index / left / sign / over first) を入れる。
   - 位相が変わったら終了し、+1 / 0 / −1 の報酬にする。
   - v2 の README にある「PPO には移植できない」は SAC/HER の部分についての話で、**分解・条件付け・リセットは PPO でもそのまま使える**。
5. **off-policy 学習の検討**: 1 手が 585 物理ステップと重いので、サンプル効率の差は大きい。Isaac Lab の skrl 統合には SAC があり、HER も実装できる。P1 を入れても PPO が伸びない場合の選択肢。

## 付録 A: 追加検証

Isaac Sim を使わず、`topology` パッケージだけで実行した (スクリプトは scratchpad に置いたもので、リポジトリには追加していない)。

### A-1. R2 除去の順序依存性

`test_knot_detect._random_ropes` で 10 seed × 3 スケール × 600 本のランダムロープを作り、交差スロットの並びを 5 通りランダムに入れ替えて `reduce_r2` → `topology_class` を比べた。

| 条件 | 比較した本数 (交差 ≥ 2) | class が異なった | 除去後の交差数が異なった |
|---|---|---|---|
| 全ケース | 32,530 | 11 (class 2 ⇔ 3) | 0 |
| 除去後の交差数が 8 以下 | 32,495 | **0** | 0 |

class が異なった 11 件は、**除去後の p-data が完全に同じ**なのに class だけ違っていた。交差が 13 個あり、§6.3 の 8 スロット打ち切りが並び順に依存したことが原因。R2 除去そのものは、この範囲で順序によらない (合流的) と言える。

### A-2. 8 スロット打ち切りによる見落とし

`IntersectionBatch.from_lists` で「独立した R1 ループ n 個 + 三葉結び (上下交互・同符号)」を直接組み立てた。ループを頭側に置くと、n = 6 (交差 9 個) で `is_overhand = False`、R2 後の class = 2 になる。尻尾側に置くと n = 7 でも class 3 のまま (結果の表は §6.3)。

## 付録 B: 用語

- **p-data**: ロープを床に投影し、端からたどったときの交点の番号・上下 (O/U)・符号 (±) を並べた位相表現 (Takamatsu et al. 2006)。3 論文も本実装も同じものを使う。
- **R1 / R2 / Cross**: 交差を 1 つ増やす輪 (R1)、2 つ増やす重ね (R2)、端で 1 つ増やす交差 (Cross)。3 論文とも R3 は扱っていない。
- **C1 / C2 / C3**: 本実装の報酬ラダーの段。輪 1 つ / 先端を輪に 1 回くぐらせた状態 / 固結び。
- **Go-Explore 型リセット**: 到達した興味深い状態を保存しておき、そこからエピソードを始める探索法 (Ecoffet et al. 2019)。TWISTED-RL が初期状態の選び方の着想として引用している。
