一言で言うと

  1. TWISTED の高レベル計画はそのまま使い、低レベルの「1 手の逆モデル」を、1 回の位相遷移を最大 M 手でこなす SAC 方策に置き換えた。
  2. 方策の条件は「次の位相状態」ではなく「行う Reidemeister 移動とそのパラメータ」ρ(A)。長さが固定されるので、交差数が違っても同じスキルを使い回せる。
  3. 報酬は、目標の遷移 +1、位相が変わらない 0、別の遷移 −1 の疎報酬だけ。初期状態は、学習中に出会った形から一様に選ぶ。TWISTED のデータは一切使わない。
  4. 交差数ごとに方策を分ける TWISTED-RL-C が最良。TWISTED が 0% だった 3-Medium / 3-Hard / 3-Eval で 44% / 46% / 61%、4-Eval で 26% (TWISTED は 10%)。3-Easy は約 3 倍速く解く。

この論文は、TWISTED の低レベル方策 (逆モデル) の限界を 3 つにまとめ、それぞれに対策を当てています §I。

02問題の定式化: 目標条件付き MDP

この論文が扱うのは、高レベルの計画で隣り合う 2 つの位相状態のあいだを低レベルで移る部分です。これを目標条件付き MDP (GC-MDP) として定式化します §III。

(Q, C, f, R, G, γ) Q : ロープの形の空間 (連続・高次元) C : 行動 = 曲線 c = (l, x, y, z_max) f : Q × C → Q シミュレータによるロープの力学 G : 目標 = 高レベルの遷移 g = (S --A--> S_g) R : Q × Q × G → ℝ 報酬 γ : 割引率 π : Q × G → C 学習する低レベル方策

+1

目標の位相状態 Sg に達した

0

今の位相状態 S のまま (形だけが変わった)

−1

それ以外の位相状態に変わった

脚注で、失敗した遷移すべてに同じ罰を与えても最適方策は同じだが、局所的には「負の報酬が溜まらないよう早くエピソードを終わらせる」方策が好まれて探索が妨げられる、と注意しています。単純な設定を選び、別の報酬の形は今後の課題としています §III 脚注 2。

03全体像

高レベル計画は TWISTED と同一です。高レベルの各移動の実行を、市販の RL アルゴリズム (SAC) で学習した多段の方策に任せます。方策は何も無い状態 (tabula rasa) から学習し、TWISTED のデータは使いません §IV。推論時は、高レベルの計画をたどりながら、次に行う遷移に応じて専用のエージェントを選びます。

04エージェントの分け方: G · A · C · AC

高レベルの遷移 (S → S′) を、移動の種類 A、元の状態の交差数 ϕ(S)、またはその両方でグループに分け、グループごとに SAC エージェントを 1 つ学習します §IV-A。

分けるほど良い点

交差数と移動の種類の組み合わせによって、難しさもデータの量と質も大きく違う。グループごとに専用の方策を学習すれば、データの偏りを明示的に抑えられる。TWISTED は 1 つの逆モデルですべての遷移を扱ったため、データ収集とデータの釣り合いに苦労した。

まとめるほど良い点

グループが少ないほど、1 つの方策が多様な遷移から学ぶので汎化しやすい。実験では、この 2 つの釣り合いが交差数ごとに分ける C 版で最も良くとれていた (§09)。

05目標の状態ではなく、遷移の種類で条件付ける

方策の入力は、ロープの形から位置だけを取り出したものと、行う移動の符号化をつなげたものです §IV-B。

目標の位相状態で条件付けると、2 つの問題があります。

  1. 長さが変わる: 交差数が増えると p-data が長くなる。同じ R1 をするだけでも、固定のネットワーク構造では可変長の入力を扱えない。
  2. 使い回せない: 目標の状態ごとに別物として扱われ、抽象化されない。

遷移の種類 (Reidemeister 移動) で条件付ければ、「R1 のやり方」のようなスキルが学べます。単純な結び目で覚えた R1 のスキルは、R1 の仕組みが同じなので、より複雑な場面にも移せる、というのがこの論文の仮説で、実験でも確かめています。

注ρ(g) の具体的な中身 (どのパラメータをどう並べるか) は論文本文に書かれていません。Yan2020 の Table I のパラメータ (index, over_index, under_index, left, sign, over_first) に相当する情報と考えられます。

06多段エピソード

TWISTED は、1 つの高レベル遷移を 1 手のエピソードとして扱いました。制御の見方では、状態から行動への 1 回きりの写像を学ぶ文脈付きバンディットに近い形です。交差が多い場面では、特定の区間を孤立させる、ロープの一部を置き直す、といった「調整」の手が必要になることが多く、この形は制約が強すぎます §IV-C。

TWISTED-RL では、各遷移を最大 M 手のエピソードにします。位相状態が変わった時点 (目標でも意図しない状態でも) か、M 手に達した時点でエピソードは終わります。エージェントは元の位相状態にとどまったまま、形を調整してから遷移を実行できます。

利点は 3 つです。複雑な操作を扱いやすい小さな手に分けられること、小さな失敗から立て直せること、そして 1 回の動作で複雑な遷移をこなすことがまれな人間のやり方に近いことです。

M の値は論文本文に書かれていません。Report.md の調査では、このリポジトリの移植元コードで 7 手でした。

07目標と初期状態の選び方

探索を重視する RL (Go-Explore) にならい、学習中の目標の選び方は、すべての高レベル遷移を広くカバーすることを狙います §IV-D。

  1. 高レベルの目標遷移 (S → Sg) をランダムに選ぶ。
  2. その遷移の出発点 S について、学習中にこれまで出会った形のうち Top(q) = S となるものから、初期の形 q を一様に選ぶ。

一様に選ぶ理由は 2 つあります。いずれはすべての有効な遷移を試せること。そして、今は苦手な難しい遷移ばかり繰り返し試して負のループに陥るのを防げることです。形を一様に選ぶと、多様な初期形で学習でき、汎化にもつながります。

交差数ごとの段階的な学習

交差数で分ける版 (C と AC) では、方策を交差の少ない順に学習します。C 版は π0 → π1 → π2 → … の順です 付録 VIII-B.2。

08学習の詳細とデータ効率

  • 最初の 2000 環境ステップはランダムな方策で動かし、多様な初期探索を確保する。その後は学習中のエージェント自身が行動を選ぶ 付録 VIII-B.1。
  • TWISTED のデータを含め、外部のデータ、手作りのデータ収集、専門家のデモは一切使わない。

09実験結果

評価の設定

環境は TWISTED と同じ MuJoCo で、すべて 5 つの乱数シードで繰り返しました。制限時間は目標 1 つあたり 30 分で、3-Medium-1h だけ 1 時間です §V-A。テストセットは、TWISTED がランダムに集めたデータでの出現頻度で難しさを決めています。

3-Medium交差 3。TWISTED のデータに 120〜130 回現れる状態 (頻度の 33 パーセンタイル)記載なし

成功率 (Table I)

  • C 版が一貫して最良。2 番目に良い版との差は、3-Medium で 44% 対 28%、3-Hard で 46% 対 38%、3-Eval で 61% 対 43%。交差数による分け方がこの問題に最も合っていることを示唆します。

10限界

著者らが挙げた限界は次のとおりです §VII。

  • sim2real: 自由なエンドエフェクタを動かしていて、運動学的な制約のあるアームではない。ロープの状態は完全にわかる前提。これらの単純化は TWISTED とまったく同じで、実機に載せる前に解決が要る。
  • 100% には遠い: medium と hard の状態では、改善したとはいえ完全な成功率には届かない。より洗練された探索戦略や、表現力の高い方策の構造が必要になりそう。
  • 手数が増える: 多段の行動は柔軟だが、実行時間が延びる。3-Easy の成功例で、高レベルの移動 1 回あたり平均 2.5 本の曲線を使った (TWISTED は 1 本)。時間が重要な用途では、成功率と実行時間のトレードオフになる。

3 本を通して見ると: Yan2020 は「1 遷移 = スプライン 1 本」で足りない場合の多段化を今後の課題に挙げ、TWISTED は SAC+HER が交差 2 で失敗することを示しました。TWISTED-RL は、同じ SAC でも「遷移ごとに分けた短いエピソード」「遷移の種類で条件付け」「到達済みの形から始める」の 3 つを組み合わせると、交差 3〜4 まで届くことを示しています。

11用語集

GC-MDP
目標条件付きマルコフ決定過程。方策が状態に加えて目標 g も受け取る。
ρ(g)
高レベル遷移 g の Reidemeister 移動とそのパラメータを表す固定長のベクトル。
η(q)
形 q から位置の成分 p だけを取り出す射影。
ϕ(S) (crossing number)
位相状態の交差数。この論文では難しさの目安にし、エージェントを分ける基準にもする。
スキル (skill)
「R1 のやり方」のように、移動の種類に結びついた再利用できる方策。
G / A / C / AC
エージェントの分け方。全部で 1 つ / 移動の種類ごと / 交差数ごと / その組ごと。
Go-Explore
到達した状態に戻ってからそこで探索を続ける、探索が難しい問題向けの RL の手法 (Ecoffet ら 2019)。
anytime performance
計算時間を横軸にとった成績。途中で止めても解けている割合がわかる。
tabula rasa
事前の知識やデータ無しに、何も無い状態から学習すること。
