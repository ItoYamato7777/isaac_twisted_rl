# v1: 固結び (overhand knot) を作る — 学習は失敗

```bash
uv run train --task Isaac-Twisted-RL-Twist-v1 --headless
```

ログ: `logs/rsl_rl/knot_tying_v1/`

> **結果: 学習は失敗した。** 4000 iteration の設定に対し 157 で打ち切った。報酬は下降し続け、
> 固結びの疎報酬は一度も発火しなかった。原因の分析と作り直しは [v2 README](../v2/README.md) §1。

シーン・物理・行動・終了判定の仕組みは [`common/README.md`](../../common/README.md) を参照。
移植元 TWISTED-RL との設計の違いは [`diff_to_TwistedRL.md`](../../../../../../docs/history/v1_diff_to_TwistedRL.md) にある。

## 1. v0 から何を・なぜ変えたか

v0 の目標は「交差を 1 つ作る」だった。v1 はこれを **固結び (overhand knot / 三葉結び)** まで広げる。

| | v0 | v1 | なぜ変えたか |
|---|---|---|---|
| **目標** | 交差 1 つ | 固結び | 本来やりたいのは結ぶこと。v0 はその最小版 |
| **密報酬** | `crossing_progress` (Δ交差数) | `knot_class_shaping` (位相ラダーのポテンシャル整形) | **交差数には抜け道がある**: 独立した R1 ツイストを 3 回作れば交差数は 3 になるが、固結びには一歩も近づかない |
| **疎報酬** | `crossing_achieved` (重み 1.0) | `overhand_achieved` (重み 3.0) | 目標が稀になったぶん重みを上げた |
| **罰則** | — | `offladder_penalty` (−0.05) | 交差はあるがラダーに乗っていない「行き止まり」の状態を軽く抑える |
| **観測** | `first_crossing` (交差 1 つ, 4 次元) | `crossing_feats` (交差 5 つ, 30 次元) + `knot_class` (4 次元) | 固結びは交差 3 つなので、1 つでは状態を識別できない。実機ではノイズの交差が 1〜2 個乗るので K=5 |
| **観測次元** | 75 | 105 | 上記の追加ぶん |
| **エピソード長** | 5 手 | 8 手 | 位相的な下限 3 遷移 × 物理的に 1 遷移 ≈ 2 手 = 6 手、に復帰ぶんを足した |
| **`gamma`** | 0.95 | **0.98** | 地平が伸びた。0.95 だと初手から見た終端報酬が 0.95^7 ≈ 0.70 まで減衰する。0.98 なら 0.87 残る |
| **`num_steps_per_env`** | 10 | 16 | エピソード長の整数倍にする。半端な値だと GAE の bootstrap が不安定になる |
| **観測の正規化** | False | **True** | 105 次元のうち 60 次元はメートル単位の位置、位相特徴 30 次元は [0,1]。正規化しないと位相側が数値的に埋もれる |
| **ネットワーク** | [256,128,64] | [512,256,128] | 観測が増え、価値関数が 4 段ラダー × 8 手を表現する必要がある |
| **`entropy_coef`** | 0.01 | 0.02 | 地平が伸び、目標が疎になったぶん探索を強めた |
| **`max_iterations`** | 2000 | 4000 | |

### 位相クラスのラダー

途中経過は 4 段の「位相クラス」で表す ([`knot_detect.py`](../../common/topology/knot_detect.py))。
三葉結びを途中まで描くと段が 0 → 1 → 2 → 3 と順に上がることを確認してあり
(`tests/test_knot_detect.py::test_partial_trefoil_walks_up_the_ladder`)、人間が結ぶ手順にそのまま対応する。

| 段 | Φ | 位相 |
|---|---|---|
| 0 | 0.00 | 交差なし / 行き止まり (独立したツイストだけ、など) |
| 1 | 0.35 | 交差 1 つ (**v0 の目標がここ**) |
| 2 | 0.70 | 絡んだ 2 交差・同符号 |
| 3 | 1.00 | **固結び** |

固結びは **厳密な `交差数 == 3` では判定しない**。尻尾に小さなループが 1 つ付くだけで交差数は 7 になり、
厳密判定では本物の固結びを取りこぼす。代わりに部分列判定を使う
(根拠と実測は [`../../next_action.md`](../../../../../../docs/history/next_action.md) 4.8.2〜4.8.3)。

### なぜ素朴なボーナスではなくポテンシャル整形なのか

`if class == 2: +0.70` のように段そのものに報酬を付けると、**2 段目に居座って毎手ボーナスを稼ぐ**のが
最適方策になってしまう。

ポテンシャル形式 `F = γΦ(s') − Φ(s)` なら、段に留まるだけでは `γ·0.70 − 0.70 ≈ −0.014` にしかならず、
登らないと得にならない。しかも Ng et al. (1999) により、**最適方策を変えないことが保証されている**。

**`gamma` は報酬整形と PPO で一致させること。** この保証はそれが前提になっている。値を二重に管理しないよう、
[`env_cfg.py`](env_cfg.py) の `GAMMA` を [`agents/rsl_rl_ppo_cfg.py`](agents/rsl_rl_ppo_cfg.py) が import している。

### `crossing_features` で直したバグ

`crossing_features` は `first_crossing_feature` の置き換えで、次の 2 点も直している。

* **正規化の分母**: 旧実装は `batch.data.shape[1]` (= バッチごとに変わる最大交差数) で割っていた。
  そのため、**同じロープでもバッチに何が入っているかで値が変わっていた** (単独では `0.333/1.333`、
  バッチ内では `0.167/0.667`)。分母を定数の `2 × 節点数` にして、全成分を `(0, 1]` に収めた。
  このバグは `tests/test_knot_detect.py::test_old_normalization_was_batch_dependent` に記録してある。
* **並び順**: `batch.data` の行は `(seg_i, seg_j)` の辞書順で、ロープを端からたどった順ではない。
  並べ替えずに渡すと、同じ結び目でもセグメントがずれただけで方策には別の並びに見える。
  ロープの走査順に並べ替えた。

旧関数は v0 の挙動を保つために残してある。

## 3. 報酬 ([`mdp/rewards.py`](../../common/mdp/rewards.py))

| 項 | 関数 | 重み (1 手あたり) | 内容 |
|---|---|---|---|
| `shaping` | `knot_class_shaping` | +1.0 | `F = γΦ(s') − Φ(s)`、Φ = (0, 0.35, 0.70, 1.0) |
| `success` | `overhand_achieved` | +3.0 | 固結びができていて、**かつ**ロープが床付近にある |
| `offladder` | `offladder_penalty` | −0.05 | 交差はあるがラダーに乗っていない |
| `grasp_shaping` | `grasp_distance_penalty` | −0.05 | `close` 終了時の指先とロープの距離 |
| `failure` | `action_failed` | −0.2 | NaN / 発散 |
| `held_up` | `held_up_penalty` | −0.1 | 手の終わりにロープが浮いたまま |

v0 の `crossing_progress` / `crossing_achieved` は `common/mdp/rewards.py` に残っており、v2 で再利用されている。

## 4. 学習前の動作確認 (2026-09-15)

| 項目 | 結果 |
|---|---|
| 単体テスト | 116 件 green (`test_knot_tying_topology.py` 69 + `test_knot_detect.py` 47)。Isaac Sim 不要 |
| 観測の配線 | 105 次元で、すべて有限。`knot_class` の各行の和が 1 |
| 報酬の重み | `step_dt` で正しく再スケールされる (`success` 3.0 → 1.0496) |
| 整形報酬の正確性 | `F = γΦ(s') − Φ(s)` の実測誤差は 8 手 × 16 env で **厳密に 0** (検証方法の注意は [`../../next_action.md`](../../../../../../docs/history/next_action.md) 4.8.8) |
| ランダム方策 (16 手 × 32 env) | class 1 が 32.4%、class 2 が 1.4%、**class 3 (固結び) が 1 回** |
| 発散 / 「離すと付いてくる」 | どちらも 0 件 |

その固結びは **交差数 5 の状態で検出された**。部分列判定が実際に効いている (厳密判定なら取りこぼしていた)。
その手の `success` が 0.0 だったのも正しい挙動で、ロープがまだ吊られていたため `rope_zmax` の条件で弾かれた。

ランダム方策では全段に到達できたが、PPO が足がかりを得るには上の段が稀すぎた (v2 README §1)。
