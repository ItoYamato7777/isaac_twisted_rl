## 0. 要旨

1. **本番の指標 (まっすぐなロープから 18 手以内に固結び) では v4 ≳ v6 ≫ v5。** iteration 100 で v4 41.6%、v6 37.9% / 22.9% (seed 42 / 43)、v5 9.6% (各 512 エピソード、標準誤差 ±2 ポイント前後)。
2. **v4 は iteration 50 でほぼ頭打ち、v6 はまだ伸びている。** chain 評価で v4 は 39.3% -> 41.6% (誤差の範囲)、v6 seed 42 は 22.5% -> 37.9%。
3. **v5 の発散対策は効いているが、段 2 -> 固結び (tuck) を学びにくくしている。** 発散で終わるエピソードは v4 の 2.9% に対して v5 / v6 は 1.2%。一方で、段 2 から始めた学習エピソードの成功率は v4 が 6% -> 27% と伸びたのに、v5 / v6 は 5〜8% のまま。v4 と v5 の違いは発散対策 (離す高さ 5〜10 cm、めり込み解消速度 0.4 m/s) だけ。
4. **v6 の観測 (次にたどる辺のリンクマスク) は v5 に対して大きく効いた。** v6 は 2 シードとも、両方のチェックポイントで v5 の 2〜4 倍の固結び率。ただし v5 は 1 シードだけ。
5. **シード間のばらつきが大きい。** v6 の 2 シードは iteration 100 で 15 ポイント離れた。1 シードどうしの 10 ポイント程度の差は結論に使えない。
6. **学習ログの `chain_est` は本番の成功率の代わりにならない。** v6 では `chain_est` 0.03 に対して chain 評価 23〜38%。v4 では `chain_est` が 0.06 -> 0.14 と伸びたのに、chain 評価は横ばいだった。
7. **(追記) v6 の切り分けでは、どの変更も chain 評価で v6 を上回らなかった。** めり込み解消速度を v4 の既定に戻すと、
   学習ログでは段 2 が v4 並みに学べるようになった (段 2 成功 0.04 -> 0.19)。しかし chain 評価 (iteration 70) は 31.2% で、
   v6 の 2 シード (35.2% / 16.0%) の間、v4 (29.7%) と同程度だった。18 手のあいだの発散も v4 と同じ 17% に戻るため。
   3 の「発散対策が tuck を妨げる」は学習ログの上では正しい (原因はめり込み解消速度で、離す高さではない) が、
   本番の成功率の差にはなっていない。詳しくは末尾の追記。

## 4. 結果からわかること

### 4.1 今の時点の最良は v4、伸びしろは v6

iteration 100 では v4 (41.6%) と v6 seed 42 (37.9%) の差は誤差をわずかに超える程度。v4 は chain 評価で
iteration 50 から伸びていない。v6 seed 42 は 50 -> 100 で +15 ポイント。同じ時間を足したときに伸びるのは v6 のほうと見込まれる (解釈)。

### 4.2 発散対策は tuck の学習を妨げている (解釈)

v4 と v5 の違いは発散対策の 2 つだけで、段 2 の学習成功率 (27% 対 8%) と chain 評価 (42% 対 10%) の両方で
v4 が大きく上回った。差は iteration 10 までは無く、学習が進んでから開いたので、初期状態の物理の差ではなく
「学べる手の差」と考えられる。tuck は掴んだ端を別の紐の下へ正確に置く手で、離す高さを床から 5〜10 cm に
上げると、落ちる間に端がずれて決まりにくくなる、という仮説が最も素直 (未確認)。v5 の README の台本の再生では
同じ設定で固結びが増えていたが、台本は正確な手を知っている。RL の探索では当たりにくくなる、ということと矛盾はしない。
離す高さとめり込み解消速度のどちらが効いているかは切り分けていない。

> **(追記で検証) この仮説は外れた。** 切り分けの結果、学習ログの段 2 を止めていたのは離す高さではなく、
> めり込み解消速度の上限 0.4 m/s だった (戻すと段 2 成功 0.19、離す高さを戻しても 0.03)。段 0 の時間切れも
> 学習前から違う (0.4 m/s で 29%、0.96 m/s で 5%) ので、「学べる手の差」ではなく物理の差も含む。
> ただし chain 評価では、0.96 m/s に戻した run は発散が増え、v6 との差は出なかった (末尾の追記)。

### 4.3 成功が稀な段では「動かない方策」に落ちる (解釈)

報酬は段が上がる +1、下がる −1、時間切れ 0。v5 / v6 の段 2 では成功が 5% しか無いので、段を崩す −1 を避けて
6 手を使い切る (0) ほうが期待値が高い。学習ログの段 2 の時間切れ 30%、chain 評価の時間切れ 55〜75% は、
この局所解に入った結果と読める。v4 では成功が十分に出たので、この局所解に入らなかった。

### 4.4 次にたどる辺の観測は効いている

v6 = v5 + `next_edge` (観測だけ) で、v6 は 2 シードとも、iteration 50 と 100 の両方で v5 を大きく上回った
(22.5 / 17.6% 対 5.3%、37.9 / 22.9% 対 9.6%)。段 0 の成功率の低下も v6 では小さい。ただし v5 は 1 シードしか
無く、v6 のシード差 (15 ポイント) を見ると v5 の別シードがもっと良い可能性は残る。

### 4.5 学習ログの `chain_est` と段ごとの成功率は、本番の成功率を表さない

`chain_est = s0 x s1 x s2` は、各段を 1 回 (最大 6 手) で上がる確率の積で、アーカイブ (他の版の方策が集めた
難しい形を含む) から始まる。chain 評価は 18 手の中で段 2 をやり直せて、出発点は自分の段 1 の方策が作った形。
そのため v6 では学習時の段 2 成功 5% から想像するより、chain 評価はずっと高い。**版の比較は chain 評価で行うこと。**

## 5. 注意・未確認の点

* 各版 1〜2 シード。v4 と v6 の順位は、シードを増やすまで確定しない。
* chain 評価は決定論的方策だけ。std 付きでサンプルした場合 (`--stochastic`) は測っていない。
* 1 GPU に 2 本の相乗りで学習したので、単独の GPU の学習 (v4 README の表) より iteration あたりの時間が約 2 倍長い。
  iteration あたりの学習の進みは同じはずだが、確かめていない。
* v5 の iteration 100 の発散 15% (iteration 50 の 2.5 倍) の理由は調べていない。
* 予定では 09:00 の停止直後に chain 評価を始めるはずだったが、評価を始めたのは 11:14 だった。

### chain 評価 (iteration 70、まっすぐなロープから 18 手以内に固結び)

| run | 固結び | 時間切れ | 発散 | 段 2 以上に到達 | 発散しなかったエピソードの中の固結び |

### わかったこと

1. **学習ログで見えた (b) の優位は、chain 評価では見えなかった。** (b) 31.2% は v6 の 2 シード (35.2% / 16.0%、平均 25.6%) の間、
   v4 (29.7%) と同程度。同じ seed 42 の v6 (35.2%) には届かない。
2. **(b) は発散を v4 の水準に戻す。** chain 評価の発散は (b) 17.4%、v4 17.2%、v6 3〜4%。発散しなかったエピソードに限ると、
   (b)・v4・v6 s42 の固結び率はどれも 36〜38% で並ぶ。(b) は段 2 を学びやすくする代わりに、18 手のあいだの発散が増え、
   差し引きで v6 と変わらない、と読める (解釈)。学習中の発散 (3.2%) が小さく見えるのは、学習のエピソードが最大 6 手で、
   段が変わればすぐ終わるため。
3. **学習ログの段 2 の成功率と時間切れは、chain 評価の良し悪しを予測しなかった。** v6 は学習中の段 2 の成功が 4〜5% でも、
   chain 評価では 18 手の中でやり直して 35% に届く (§4.5 と同じ)。**中間報告の「原因はめり込み解消速度」は学習ログだけに
   基づいた結論で、本番の指標では確かめられなかった。**
4. **シード差が大きい。** v6 の 2 シードは iteration 70 で 19 ポイント離れた (iteration 100 では 15 ポイント)。1 シードどうしの
   切り分けでは、10〜15 ポイントの差は判別できない。
5. (a)・時間切れの罰則・段 2 の割合は、chain 評価で v6 の平均を下回るか同程度で、改善は見られなかった。時間切れの罰則は
   段 2 に届く割合を 46% に下げ、発散を 20% に上げた (段を崩す・乱暴な手が増えたと読める。解釈)。

このため、計画していた v7 (= v6 + (b)) の確認の学習 (3 シード) は始めていない。

### 追記の後の状態

* `versions/v7/` は「v6 + めり込み解消速度を v4 の既定に戻す」(= 上の (b)) として作ってあるが、**確認の学習はしていない**
  (chain 評価で v6 を上回る根拠が無いため)。
* 時間切れの罰則の報酬項 (`stage_time_out`) は、効果が見えなかったのでコードから削除した。結果はこの追記にだけ残る。

### 追記の後の次の候補

1. **シードを増やして決着をつける。** v6 + (b) (= v7) を seed 43 / 44、v6 を seed 44 で回し、各 3 シードで比べる
   (GPU 1 枚に 2 本で約 13.5 時間)。シード差 (15〜19 ポイント) より大きい差があるかを確かめる。
2. **めり込み解消速度の中間値。** 0.6〜0.7 m/s で、段 2 を学べることと発散の少なさを両立できるか。学習の前に
   `demos/divergence_bench.py` とゲート 1 の台本の再生で発散と固結びを測る。
3. **評価そのものを強くする。** 確率的な方策での chain 評価 (`--stochastic`)、10 iteration ごとのチェックポイントでの
   学習曲線、評価のエピソード数・シードを増やす。
